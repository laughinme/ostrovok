# Расхождения фронтенда и бэкенда

Проверено 28.10.2026. Бэкенд взят из `origin/main`, коммит
`c10220b6dda441168476c7ca9f131b0c403443f7`. Локальный `frontend/` — TanStack Start;
другие сессии продолжают его менять. Серверные файлы перенесены без общего merge
и без замены локального интерфейса. Этот файл описывает оставшуюся работу после интеграции.

## Уже соединено

- Каталог и карточка: `GET /api/v1/hotels`, `GET /api/v1/hotels/{uuid}`.
  В выдаче реальные идентификаторы и координаты, серверные факты и демо-цены.
- Поиск: `POST /api/v1/intents` → `POST /api/v1/searches`.
  Текущие восемь критериев преобразуются в ключи реестра; ранжирование,
  вероятности и общий балл возвращает сервер. Бюджет передаётся в `trip`.
- Переход к отелю сохраняет `sid`: `GET /api/v1/searches/{sid}` возвращает
  рекомендацию номера, фасада, этажа, риск и даты для заявки.
- Сравнение 2–3 отелей: `POST /api/v1/compare`, без поиска UUID в локальных моках.
- Доказательство: `GET /api/v1/facts/{id}` — метод, источники, оговорки и история.
- Заявка: `POST /api/v1/bookings` с настоящими ID категории и тарифа, датами,
  количеством гостей и пожеланиями. Вход демо-гостем `guest_anna`; это демо-бронь,
  оплата не производится, ответ отеля симулирует сервер.
- Поездки: `GET /me/trips?limit=50`, `GET /trips/{id}` с polling до ответа отеля,
  `POST /trips/{id}/feedback`; переход к поездке после заявки, серверные ожидания и оговорки.
- Кабинет: демо-вход `hotelier_salut`, серверные вопросы, ответы, подтверждение
  и исправление фактов; после сохранения связанные данные инвалидируются.
- Запросы браузера идут через `/api/v1` на своём домене. Nitro проксирует API
  на Fly.io по умолчанию; Docker gateway направляет API в локальный backend.
  Dockerfile фронта заменён с Next.js на TanStack Start/Nitro.

## Проверка и запуск

Обычный локальный фронт: `cd frontend && npm run dev` → `http://localhost:5173`.
По умолчанию используется `https://okno-api.fly.dev`, ключ LLM не нужен.
Для своего API: `BACKEND_URL=http://127.0.0.1:8000 npm run dev`.
При production-сборке адрес прокси задаётся через `BACKEND_URL` во время сборки;
для серверной загрузки данных нужно такое же окружение при запуске.

Полный локальный стек: `cp .env.example .env && docker compose up --build` → `http://localhost:8080`.
На Apple Silicon есть `make up-native`.
Типы API: `make openapi`, затем `cd frontend && node scripts/generate-api.mjs`.
Проверки фронта: `npm run check`. Визуальные снимки: `design/captures/backend-integration/`.
