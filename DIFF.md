# Аудит фронтенда и граница демонстрационных данных

Проверено 29.10.2026. Фронтенд использует API `/api/v1`; локальный транспорт
включается только cookie режима «Демо». Ошибка или отсутствие данных обычного API
не переключают приложение на локальные данные.

## Исправлено в аудите

| Область               | Результат                                                                                                                                                                                                                                       |
| --------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Аккаунт гостя         | Убран автоматический вход в `guest_anna`. Вход, регистрация, восстановление через refresh-cookie и CSRF, выход. Личные разделы требуют нужную роль. Учебные аккаунты сервера выбираются явно и подписаны.                                       |
| Гостевой каталог      | Синтетические фотографии, отзывы, удобства и описания не прикрепляются к API-отелям. Ошибка фотографии показывает отсутствие фото, без демонстрационной панорамы. Демонстрационные цены и рейтинг подписаны.                                    |
| Подборки              | Счётчики и условия поступают из `/moods`; полный набор чипов и месяц передаются в поиск. Фиксированные цифры остаются только в явно обозначенном локальном демо.                                                                                |
| Пожелания             | Отображаются все серверные чипы, их параметры сохраняются при редактировании. Доступны важность, удаление, подсказки, предложения ослабить условия и исследование неизвестного. Поиск не добавляет неуказанные предпочтения или скрытый бюджет. |
| Изменение поиска      | Даты, взрослые, дети и бюджет доступны в выдаче. Добавленное пожелание сохраняется при последующей правке фильтров. Старое исследование не подменяет результат после сброса.                                                                    |
| Профиль вкуса         | `/profile`: чтение, веса, выключение персонализации, удаление. Персональный поиск использует токен текущего гостя.                                                                                                                              |
| Номера и заявки       | Заявка использует текущий аккаунт. Вместимость проверяется по сумме взрослых и детей. Состав гостей не сокращается незаметно. Нет фиксированного ноября в расчётах без заданной даты.                                                           |
| Поездки               | Реальные поездки загружаются из аккаунта. Локальные демо-заявки сохраняются и открываются после обновления страницы. Подготовленные примеры поездок показываются только в «Демо».                                                               |
| Избранное и сравнение | Добавлена страница `/favorites`; сравнение переживает обновление страницы. Хранилища демо и обычного режима разделены.                                                                                                                          |
| Кабинет отеля         | Объект выбирается по назначению текущего аккаунта, вместо жёсткой привязки к «Салюту». Подключены разметка категорий по сторонам и этажам, заявки и решения, спрос за 7 дней и уведомления.                                                     |
| Похожие варианты      | Под страницей отеля доступны «Тише», «Дешевле», «Ближе к пляжу» через API похожих отелей; переход сохраняет серверный поисковый контекст.                                                                                                       |
| Масштаб выдачи        | Карточки загружаются на экран порциями по 20. Близкие отели группируются на карте; выбранный отель остаётся отдельным маркером.                                                                                                                 |
| Пустые кнопки         | Вложение читает описание поездки из `.txt`, проверяет размер и пустой файл. Микрофон запускает распознавание речи браузера; в неподдерживаемом браузере кнопка не показывается.                                                                 |
| Доступность           | Подписаны кнопки выдачи, состояния фильтров, поля и переключатели; интерактивные области новых элементов не меньше 44 px. Диалог входа поддерживает клавиатуру и Escape. Навигация сворачивается на узких экранах.                              |

## Что в прототипе остаётся демонстрационным

Это граница доступных данных, а не скрытые фронтенд-моки:

- API предоставляет `priceFromDemo`, `priceDemo`, `HotelDemoOut` и учебные категории
  номеров. Реальной инвентаризации, платежей и коммерческого бронирования в контракте
  нет. Интерфейс явно сообщает, что цены, рейтинги, категории и ответы симулятора
  демонстрационные; оплата не выполняется.
- Учебные аккаунты сервера общие. Для личных поездок доступна регистрация своего
  аккаунта; анонимный гость ни в один учебный аккаунт автоматически не входит.
- Фотографий реальных отелей в контракте нет. Показывается подписанная заглушка;
  фотографии на лендинге служат для настроения и имеют атрибуцию.
- В контракте нет анализа изображений. Вложение принимает текст; распознавание
  голоса зависит от возможностей и разрешений браузера.
- API не хранит список избранного между устройствами. Избранное хранится в браузере,
  сравнение — в пределах браузерной сессии.
- Нет отдельного API назначения обычному аккаунту отельера объектов и исторической
  ленты его действий. Используются назначения выбранных серверных персон; история
  действий кабинета честно обозначена как история текущего открытия.
- Внешняя карта требует доступа к тайлам OpenFreeMap. При недоступности показывается
  ошибка, список отелей остаётся доступен. Крупные динамические модули карты и 3D
  остаются ограничением загрузки на медленной сети.

## Проверки

`cd frontend && npm run check` выполняет ESLint, проверку FSD, отсутствие комментариев,
TypeScript, Vitest и production-сборку. Проверки изоляции аккаунтов и разделения
локального/обычного API включены в тесты. Визуальные снимки и результаты браузерных
прогонов находятся в `design/captures/frontend-audit/` (каталог не коммитится).

Браузерные сценарии: анонимные личные разделы, явный вход и восстановление сессии,
профиль, выдача, сравнение, избранное, создание заявки в API и проверка вместимости, ошибка API без
подстановки локальных отелей, демо-поиск → уточнение → локальная заявка → поездка
без обращений к API. Экранные проверки: 1440×900 и 390×900; дополнительные состояния
проверяются на 390×844 и 1366×768. Итог: 34 файла Vitest, 172 теста успешно; семь сквозных сценариев успешно.
Кабинет отельера и консоль проверены с разными явно выбранными аккаунтами.
В прогоне лендинга вперёд и назад на 1440×900 и 390×844 нет ошибок JavaScript
или подозрительно пустых кадров; видео и контактные листы сохранены рядом со снимками.

Состав коммита дополнительно выгружен из Git-индекса в отдельную папку и прошёл
полный `npm run check`: 33 файла Vitest, 171 тест, типы, линтер и production-сборка.
Это проверяет сборку без зависимости от незавершённых соседних изменений.

Параллельные изменения визуализаций отеля и серверных маршрутов не входят в коммит
этого аудита; рабочее дерево общее, поэтому проверки также учитывают их текущее состояние.
