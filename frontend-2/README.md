# Луч — независимая версия 02

Полноценный интерактивный frontend для трека «О!дин шаг до идеального отеля». Новая визуальная концепция и реализация находятся целиком в `frontend-2/`. Существующие `frontend/`, backend и корневые настройки не используются и не изменяются.

**Это демонстрация продукта.** Шесть отелей вымышлены; цены, отзывы, характеристики, источники и проценты достоверности подготовлены для демонстрации. Фото иллюстративные. AI, георасчёты, ответы отельера и запрос номера симулируются локально. Реальные сообщения, платежи и бронирования не выполняются.

## Запуск

Требуется Node.js 22.12+ и npm. Проверено на Node.js 25.6.1.

```sh
cd frontend-2
npm ci
npm run dev
```

Открыть **http://127.0.0.1:5174**. Порт специально отличается от первой версии. Если он занят, остановите использующий его процесс или передайте другой порт: `npm run dev -- --port 5175`.

Ключи, `.env`, backend и сторонние сервисы не нужны. После установки зависимостей приложение работает без интернета: изображения, шрифты, каталог и схематичная карта включены в проект.

Production-сборка:

```sh
npm run build
npm run preview
```

Предпросмотр: **http://127.0.0.1:4174**. Для размещения на статическом хостинге отдавайте `dist/` и перенаправляйте неизвестные пути на `index.html`, чтобы работали прямые ссылки SPA.

## Что можно попробовать

| Раздел               | Возможности                                                                                                         |
| -------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `/`                  | Поиск своими словами, пять районов, даты и гости, выбор настроения, быстрые критерии                                |
| `/search`            | Пять шагов агентного исследования, текущая задача, собранные критерии; анимацию можно пропустить                    |
| `/results`           | Ранжирование по пожеланиям, двойной вес главного приоритета, бюджет, обязательная тишина, сортировка, пустая выдача |
| Карта в выдаче       | Связанные с карточками метки, масштаб, слои отелей, шума и мест поблизости; геометрия схематичная                   |
| `/hotel/more-vnutri` | Галерея, переключение этажа и стороны, шум днём/ночью, окружение, источники, сохранение демозапроса номера          |
| `/compare`           | До трёх отелей, единая таблица, только различия, изменение приоритета, источники фактов                             |
| `/partner`           | Обзор, редактирование характеристик, три темы диалога с агентом, извлечение данных и явное подтверждение            |
| `/how`               | Интерактивное объяснение источников, ограничений и механики доверия                                                 |
| Избранное            | Сохранённые отели доступны по сердечку в шапке                                                                      |

Параметры поездки передаются в URL. Избранное, сравнение, профиль отеля и демозапросы сохраняются в `localStorage` этого браузера. При запрете доступа к хранилищу текущая сессия остаётся работоспособной, но изменения не переживут перезагрузку.

## Сценарий для демонстрации, 3–4 минуты

1. На главной ввести: **«Хочу тихий отель с видом на море и закат, недалеко от пляжа»**. Запустить поиск и показать работу агентов.
2. В выдаче переключить слой шума. Выбрать метку «Тихой гавани», затем открыть «Море внутри». Добавить оба отеля в сравнение.
3. На странице «Море внутри» выбрать 2-й этаж, затем 6-й: изменится состояние видимости. Поменять сторону на двор. Во вкладке «Что мы узнали» открыть источник любого вывода.
4. В сравнении выбрать главным приоритетом тишину: «Тихая гавань» получит более высокую оценку по этому критерию. Посмотреть компромисс по дороге до моря.
5. В кабинете отельера нажать «Ответить Лучу», ввести **«Делюкс на 4–6 этажах выходят на юго-запад»**. Проверить извлечённые данные и нажать «Подтвердить и применить».
6. Вернуться на страницу «Море внутри»: категория номера теперь подтверждена отельером. Сохранить демозапрос на нужный этаж.

Для сброса демонстрации удалить в DevTools → Application → Local Storage только ключ **`luch-v2-state-v1`** и обновить страницу.

## Архитектура

React 19 + TypeScript, Vite, React Router, Lucide. Обычный CSS с собственной системой токенов, адаптивными сетками и поддержкой `prefers-reduced-motion`. Компоненты и дизайн первой версии не импортируются.

```text
src/
  App.tsx                 маршруты, шапка, избранное, footer, обработка ошибок
  data.ts                 каталог, характеристики, источники, настроения
  search.ts               разбор запроса, бюджет, ранжирование, URL поездки
  state.tsx               состояние с проверкой сохранённых данных
  components/             поиск, карта, карточка отеля, диалоги и UI
  pages/                  главная, агенты, выдача, отель, сравнение, кабинет
  styles.css              дизайн-система и адаптивная вёрстка
public/
  images/                 локальные иллюстративные фото
  fonts/                  Golos Text и лицензия OFL
tests/                    браузерные сценарии Playwright
artifacts/                проверенные скриншоты desktop и mobile
```

Поиск использует локальные правила для восьми групп пожеланий: тишина, море, закат, пляж пешком, работа, природа, дети, питомцы. Неизвестные пожелания явно помечаются как неподдерживаемые; полноценного языкового понимания нет. Оценка совпадения — среднее демооценок выбранных характеристик, главный приоритет получает двойной вес. Бюджет и район фильтруются отдельно.

Вид из окна меняется по заранее заданному порогу этажа и стороне фасада. Это иллюстрация интерфейса геомодели, а не фактический расчёт по DEM. Шум и солнечная траектория также иллюстративные. Упоминания OSM и DEM в источниках показывают предполагаемую структуру доказательства; реальные выгрузки этих источников приложение не использует.

Ответ агента в кабинете извлекается регулярными правилами, показывается пользователю для проверки и применяется только после подтверждения. Нераспознанный ответ вызывает уточняющий вопрос. Обновлённые условия тишины, питомцев и номера становятся видны в фактах гостевой карточки; при этом исходные модельные оценки ранжирования не пересчитываются из свободного текста.

## Проверки

Для первого запуска браузерных тестов установить Chromium:

```sh
npx playwright install chromium
npm run check
```

Отдельно:

```sh
npm test          # предметная логика: запрос, бюджет, район, сортировка, приоритет, URL
npm run build     # строгая проверка TypeScript и production-сборка
npm run test:e2e  # сценарии в desktop Chromium и мобильном viewport
```

Playwright поднимает локальный сервер самостоятельно или использует уже запущенный на порту 5174. Проверяются переходы, фильтры, карта, галерея, этаж, источники, сравнение, избранное, профиль отельера, демозапрос, перезагрузка, некорректные ссылки, загрузка фото и отсутствие горизонтального переполнения. Итоговые скриншоты сохраняются в `artifacts/`.
