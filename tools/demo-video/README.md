# Запись презентации О!кно

Локальная студия записи и монтажа. Не входит в Docker приложения.
Исходные видео, снимки и экспорт хранятся в `.private/video-production/`, вне git.

`capture-lib.mjs` пишет Chromium через Playwright Screencast в 1440×810, 60 fps.
Прокрутка идёт через `requestAnimationFrame` с плавным разгоном и торможением;
курсор движется по дуге, перед кликом есть пауза и видимый импульс. Каждый
сюжет записывается отдельно, вместе с координатами акцентов и диагностикой API.
Отсутствующая цель или акцент за границами кадра останавливают запись.

```sh
cd tools/demo-video
npm ci
npx playwright install chromium
npm run capture
npm run prepare
npm run dev
npm run render
npm run finalize
```

Приёмы подачи: сглаженный курсор и приближения, как в
[Screen Studio](https://screen.studio/guide/cursor), аннотации и отдельные
сцены, как в [Recordly](https://github.com/DougNix/recordly).
Монтаж строится в [Remotion](https://www.remotion.dev/docs/).
Скилл `remotion-best-practices` уже установлен; установка чужого рекордера не нужна.

`DEMO_URL` меняет адрес приложения. `CAPTURE_OUT` меняет каталог дубля.
`CAPTURE_PART=hotel npm run capture` переснимает только соответствующий фрагмент,
сохраняя остальные сцены. Части: `guest`, `compare`, `overview`, `hotel`, `source`, `booking`,
`partner`, `agents`, `agents-result`, `platform`. Сначала нужен
полный запуск или `guest`: он запоминает ссылку на выбранный отель локально.

`npm run prepare` проверяет разрешение и частоту кадров, конвертирует исходники
в H.264, загружает Onest с Google Fonts и создаёт оригинальную тихую подложку
без сторонней музыки. Экспорт — 1920×1080, 60 fps. Звук можно отключить в
`Root.tsx`, поменяв `music` в возвращаемых свойствах.

Титры, камера, подсветки и переходы вычисляются по кадрам. Приближение следует
координатам реального элемента; рамка подсветки движется вместе с экраном.
Полный экран сохраняется между акцентами. Ожидание агента между отдельными
сценами вырезано, это явно подписано в ролике. Запись обращается к настоящему
API; создание заявки и ответ отельера меняют демонстрационные данные сервера.

`edits.json` задаёт обрезку пауз в начале и конце каждой сцены в секундах.
Действия и прокрутка сохраняют исходную скорость. Подсветки автоматически
сдвигаются вместе с обрезкой; переходы между сценами занимают 24 кадра.
Пересборка монтажа не требует повторных обращений к API и LLM.

`npm run finalize` добавляет главы, проверяет кодеки, число кадров и длительность,
декодирует фильм для контактного листа и пишет `verification.json`, `chapters.txt`,
`poster.jpg`, `storyboard-final.jpg` рядом с MP4. Неудачный дубль не заменяет
ранее записанный файл сцены; ошибки API и runtime останавливают запись.

В сравнение переходим по ссылке внутри приложения: выбор отелей хранится
в памяти страницы. Полная перезагрузка очищает его. Перед записью проверяем,
что на странице появился выбранный отель, чтобы пустое состояние не попало в фильм.
