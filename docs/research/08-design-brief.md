# 08. Бриф для дизайн-сессии

Для кого: параллельная сессия, которая делает дизайн и фронтенд-прототип со скиллом `design-studio` и
Mobbin MCP. Читать вместе с [`PRODUCT.md`](../../PRODUCT.md) (аудитории, тон, ограничения) и
[05](05-concept-and-features.md) (концепция целиком).

## 0. Как пользоваться этим брифом

- Ответы на вопросы kickoff из `design-studio` уже есть в `PRODUCT.md` и здесь. Kickoff можно не
  проводить заново: сразу исследование референсов → направления → гейт 1.
- Пользователь не дизайнер. Решаем сами, его зовём только на три гейта: **направление**,
  **интерактивная концепция**, **ревью**.
- Прототип собираем на моковых данных по контракту из [§9](#9-контракт-данных-для-моков), чтобы потом
  подключить настоящий бэкенд без переделки экранов.
- Результаты дизайн-сессии: `DESIGN.md` (корень), `design/references/`, `design/decisions.md`,
  `design/storyboard.md` (для лендинга), прототип во фронтенде.

## 1. Что уже решено

| Решение | Значение |
|---|---|
| Устройства | **Десктоп основной** (проверяем на 1440 и 1366). Телефон (390) адаптивом во вторую очередь: всё работает и читается, полировка позже |
| Язык | Русский интерфейс |
| Регион и данные | Большой Сочи; OSM, Copernicus DEM, Open-Meteo; базовые карточки — мок с пометкой «демо» |
| Фото | Чужих фото отелей нет и не будет. Картинки — наши визуализации (панорамы, фасады, карты, профили) и Wikimedia CC с атрибуцией |
| Вход | Лендинг и приложение на одном экране: поле желания превращается в рабочее пространство без перезагрузки |
| Поиск | Без классических фильтров: холст намерений из чипов с важностью |
| Тон | Честный, точный, спокойный; никогда не реклама и не «магический AI» |
| Стек фронта (предложение) | Next.js + TypeScript, Tailwind, shadcn/Radix как поведение (внешний вид свой), MapLibre GL для карты. API библиотек сверять через Context7 |

## 2. Что решаем на гейтах

### Визуальное направление (гейт 1)

Пользователь пока не выбрал и просит решить это в дизайн-сессии. Его ориентиры:

- тёмная тема в духе современных продуктов вроде Vercel — техничная, точная;
- или светлая тема;
- держаться базовых черт Островка (их синий и салатовый со слайдов открытия) — хорошо, но копировать
  не обязательно. Продукт задуман как переосмысление, которое Островок может встроить к себе.

Предлагаем отрисовать 2–3 направления, которые отличаются идеей, и каждое вывести из мира продукта:
побережье, вечерний свет, рельеф, топографические карты, архитектурные чертежи фасадов, навигационные
карты. Примеры идей, не обязательные:

1. **«Чертёж»**: точный технический интерфейс (тёмный или светлый), фасады и горизонты как инженерная
   графика, один тёплый сигнальный цвет — цвет заката.
2. **«Побережье вечером»**: светлый спокойный интерфейс, палитра из моря, камня и вечернего солнца,
   визуализации как акварельно-точные иллюстрации данных.
3. **«Островок, переосмысленный»**: близко к фирменному синему и салатовому, но со своей типографикой и
   визуальным языком доказательств.

Учитывать «пол качества» из `design-studio`: никаких тёмно-чёрных фонов с неоновым акцентом,
фиолетово-синих градиентов, стандартных сеток карточек и шрифтов «по привычке». Проверять кириллицу в
каждом шрифте.

### Интерактивная концепция (гейт 2)

Ключевое место для изобретения — вход и выдача. Предлагаем сравнить две концепции на живых данных и
пройти по сценарию из трёх задач: найти, сравнить, поменять условие и увидеть последствия.

- **Концепция A, «Холст»**: поле желания → чипы над выдачей → список слева, карта справа. Правка чипа
  видимо перестраивает выдачу.
- **Концепция B, «Разговор-конструктор»**: помощник ведёт короткий диалог, каждый ответ превращается в
  чип на холсте, выдача растёт рядом с диалогом.

Можно смешать, но одна концепция должна доминировать. Наша рекомендация по умолчанию — A, с элементами
B в помощнике запроса.

### Название

Рабочее «О!кно». Варианты в [05 §13](05-concept-and-features.md#13-название-варианты). Пользователь
выбирает. В макетах держим название в одном месте, чтобы заменить быстро.

## 4. Экраны подробно

### 4.1. Вход-лендинг (`/`)

**Задача.** За 5 секунд объяснить, чем это отличается от обычного поиска, и сразу дать начать.

**Первый экран:**
- Мысль продукта одной фразой, например: «Узнайте, каким будет ваш номер, до того как приедете».
- Поле желания с примерами-подсказками («тихо, закат над морем, без подъёмов, ноябрь»), микрофон,
  кнопка загрузки фото «хочу такой вид».
- Ряд подборок-настроений с подзаголовком-доказательством: «Проснуться с морем — 23 отеля, где море
  видно из кровати» (числа будут из данных).
- Визуальный герой: наши собственные данные. Например, рельеф побережья по DEM в вечернем свете или
  панорама горизонта из реального номера. Не стоковое фото.

**Ниже первого экрана** (для первого визита и для жюри), коротко:
1. Откуда мы знаем: три источника (расчёт, открытые данные, отельер).
2. Как выглядит доказательство: живой пример «почему мы так думаем».
3. Для отельеров: «отвечаете на 3 вопроса вместо анкеты».
4. Для разработчиков: API и MCP.
5. Атрибуция данных.

**Ключевое движение (сигнатурный момент продукта).** Человек начинает печатать или кликает подборку →
мысль продукта уходит, поле поднимается и превращается в холст намерений, снизу «вырастают» выдача и
карта. Это один непрерывный переход (shared element), не смена страницы. Обратно — тем же путём.

**Состояния:** пустой ввод, ввод в процессе (подсказки чипов), голос (идёт запись, распознано),
загрузка фото (разбор, найденные признаки), без ключа LLM (подсказки из словаря, фото → выбор из
галереи панорам).

### 4.2. Холст намерений и помощник запроса

**Задача.** Показать, как система поняла желание, и дать поправить без фильтров.

- Чип = желание + важность (обязательно / важно / приятно) + способ проверки: «посчитаем», «спросим у
  отеля», «не можем проверить». Неизвестные желания выглядят иначе и ведут к живому исследованию.
- Параметры поездки (даты, гости, бюджет) — тоже чипы, но визуально отделены от желаний.
- Подсказки помощника под полем: «Добавить: до пляжа без подъёма?», «Для заката важны даты — когда
  едете?». Не больше 1–2 одновременно.
- Профиль вкуса подмешивает веса, и это видно: «учли ваш профиль: тишина важнее вида» (можно выключить).
- Правка чипа (важность, удаление, добавление) видимо перестраивает выдачу: карточки переезжают,
  проценты меняются.

**Состояния:** пусто, 1 чип, 8+ чипов (перенос, сворачивание), конфликт желаний («море» и «до 4 000 ₽»
почти не пересекаются → честная подсказка), непроверяемое желание.

### 4.3. Выдача: список + карта

**Карточка соответствия:**
- Название, район, процент совпадения, риск разочарования.
- Строки ✓ / ⚠ / ✗ по каждому чипу, коротко: «✓ закат над морем с ЮЗ-фасада, 4+ этаж».
- Одна строка компромисса: «вид на море есть, но с этой стороны ж/д».
- Визуал карточки — наша миниатюра: силуэт горизонта из лучшего номера, схема фасадов или кусок карты.
- Цена (демо) и лучшая категория номера под запрос.
- Действия: открыть, в сравнение, «как этот, но…».

**Карта:**
- Отели как метки с процентом. Наведение на карточку подсвечивает метку и наоборот.
- Слои: шум, конусы обзора фасадов, маршруты до пляжа, линия заката в даты, стройки.
- По желанию — 3D-здания по высотам.

**Состояния:** загрузка (скелеты в форме карточек), ноль результатов (что ослабить, с прогнозом:
«уберите „до 4 000 ₽“ — будет 7 отелей»), 1 результат, много, частичные данные (часть фактов ещё
считается), идёт живое исследование.

### 4.4. Сравнение

Таблица 2–3 отелей или номеров: строки — чипы пользователя, ячейки — ✓/⚠/✗ с коротким фактом и
уверенностью. Сверху итог: «A лучше по закату, B — по тишине». Открывается из лотка внизу выдачи.

### 4.5. Страница отеля «Как это будет» (`/hotels/:id`)

**Задача.** Дать пережить пребывание до брони и снять сомнения доказательствами.

Блоки по порядку важности (порядок подстраивается под чипы пользователя):

1. **Шапка:** название, район, процент совпадения с вашим запросом, строки ✓/⚠/✗, кнопка брони.
2. **Ваше окно.** Панорама горизонта на 360° или на сектор фасада: линия рельефа, море, подписанные
   вершины, застройка. Управление: фасад (СВ / ЮВ / ЮЗ / СЗ), **слайдер этажа** (картинка меняется
   вживую: на 2-м этаже дом напротив, на 5-м — море), даты (точка и дуга солнца, время заката).
3. **Ваша ночь.** Схема здания сверху: шум по сторонам днём и ночью, источники (дорога, ж/д, бар) с
   расстояниями, что рядом работает ночью.
4. **Ваше утро.** Маршрут до пляжа на карте + профиль высот: время туда и обратно, ступени, переходы
   через ж/д, тип пляжа.
5. **Ваши даты.** Температура воздуха и воды, осадки, световой день, закат по дням поездки.
6. **Какой номер брать.** Категории номеров с привязкой к фасадам и этажам (если отельер разметил) и
   рекомендация запроса.
7. **Что ещё мы знаем.** Остальные факты, сгруппированы, с источником и датой.
8. **Чего мы не знаем.** Честный список с действием «спросить отель».

У каждого факта значок уверенности и кнопка «почему мы так думаем».

**Состояния:** нет разметки фасадов (показываем по фасадам здания без привязки к номерам, ⚠), нет
высоты здания (широкий разброс уверенности), факт устарел (пересчитывается), конфликт источников.

### 4.6. Панель «Почему мы так думаем»

Выезжает справа с любого факта. Содержимое:
- Утверждение и область действия: «Море видно из окон ЮЗ-фасада с 4-го этажа».
- Уверенность словами + число + что она значит: «в 82 из 100 симуляций с учётом погрешности высот
  домов море видно».
- Метод: «расчёт горизонта по рельефу Copernicus DEM 30 м и зданиям OSM».
- Доказательство: картинка (панорама, схема, маршрут, график) с атрибуцией.
- Источники и даты, история версий («было: нет; стало: да после ответа отеля 12.10»).
- Что может пойти не так: «деревья не учитываем; высота соседнего дома оценена».
- Действия: «проверить самому» (объект в OSM, слой на карте), «сообщить об ошибке».

### 4.7. Живое исследование

Лента шагов агента, появляется в выдаче, когда есть непроверенное желание:
«Не знаю, пускают ли с собакой 30 кг → по карте не посчитать → спрашиваю 5 отелей… ✓ Отель A ответил:
можно до 40 кг, 1 500 ₽/сутки». Каждый шаг — короткая строка с иконкой инструмента и статусом. Выдача
обновляется по мере ответов, изменения подсвечиваются. Та же лента в подробном виде — в консоли
(`/console/agents`).

### 4.8. Бронь в один шаг (`/hotels/:id/book`)

Один экран: категория номера, даты, гости, **автоматически сформированный запрос к отелю** (можно
поправить), цена (демо), имитация оплаты. После — статус «запрос отправлен → отель подтвердил ЮЗ-сторону,
5 этаж». Никаких лишних шагов.

### 4.9. Поездка (`/trips/:id`)

- Статус запроса к отелю.
- «Что вас ждёт»: закат в ваши даты, погода и вода, маршрут до пляжа, подтверждённая сторона.
- После дат поездки: «Всё было так, как мы обещали?» — по каждому обещанному факту да / нет / частично.

### 4.10. Профиль вкуса (`/me`)

Человеческим языком: «тишина важнее вида», «не любите подъёмы», «обычно едете осенью». Откуда вывод
(«3 из 4 броней — во двор»). Можно поправить, выключить или сбросить. История броней и сохранённых
отелей (демо).

### 4.11. Кабинет отельера (`/partner/*`)

- **Обзор**: что Островок знает об отеле — факты с доказательствами, «подтвердить» / «исправить»,
  заметные конфликты («мы посчитали иначе — вот почему»).
- **Вопросы**: карточки вопросов, отсортированные по ценности, с причиной («34 гостя за неделю искали
  тишину»). Ответ текстом, голосом или выбором из вариантов. После ответа видно, что изменилось («ваш
  отель теперь находится по запросу „тихо“»).
- **Разметка фасадов**: силуэт здания сверху на карте, стороны кликабельны, к каждой — категории номеров
  и диапазон этажей. Сразу видно следствие: «с этой стороны: море с 4-го этажа, ж/д в 60 м».
- **Запросы гостей**: принять, предложить альтернативу.
- **Спрос**: что ищут в районе, что из этого у отеля есть и не подтверждено.
- **Уведомления**: «рядом стройка — проверьте вид».

### 4.12. Консоль знаний (`/console/*`)

Плотный рабочий интерфейс для широкого экрана.
- **Реестр характеристик**: таблица — название, способ (расчёт / открытые данные / отельер), покрытие,
  средняя уверенность, срок годности, когда пересчитано.
- **Новая характеристика**: поле текста → агент показывает рецепт (цепочка инструментов) → пробный
  прогон на 5 отелях с результатами → «опубликовать» → характеристика появляется в поиске.
- **Трассы агентов**: список запусков, внутри — шаги: инструмент, вход, выход, решение, время.
- **Конфликты**: пары «источник А против источника Б», правило разрешения, итог, что ушло отелю.
- **Лента изменений**: событие → пересчёт → последствия (у каких отелей что поменялось, кого уведомили).
  Кнопка демо «Добавить здание» (рисуем полигон рядом с отелем → вид пропал).
- **Добавить отель**: выбор точки или объекта OSM → агент изучает вживую → карточка готова.
- **Качество**: точность по характеристикам на эталоне, диаграмма калибровки, покрытие, доля вопросов к
  отельерам, nDCG поиска. Графики — по скиллу `dataviz`.

### 4.13. Для разработчиков (`/developers`)

Коротко: что даёт API, пример запроса и ответа с доказательствами, как подключить MCP к своему агенту,
ссылка на OpenAPI-документацию. Живой пример: внешний агент спрашивает «номер с закатом над морем в
ноябре».

## 5. Ключевые компоненты

| Компонент | Где используется | Заметки |
|---|---|---|
| Чип намерения | Холст, подборки, помощник | Важность, способ проверки, состояние «неизвестно / исследуется» |
| Карточка соответствия | Выдача | Процент, ✓/⚠/✗, компромисс, наша миниатюра вместо фото |
| Строка факта | Везде | Утверждение, область действия, значок уверенности, «почему» |
| Значок уверенности | Везде | Слово + цвет + число по наведению; одинаков во всех поверхностях |
| Панель доказательства | «Почему мы так думаем» | См. §4.6 |
| Панорама горизонта | Ваше окно, миниатюры, фото-поиск | Слайдер этажа, фасад, солнце по датам. Самая узнаваемая визуализация продукта |
| Схема шума по фасадам | Ваша ночь, карточки | Вид сверху, день / ночь |
| Профиль маршрута | Ваше утро | Высоты, ступени, переходы, время туда и обратно |
| Климат в даты | Ваши даты | Маленькие графики по дням |
| Лента агента | Живое исследование, консоль | Шаги с инструментами и статусами |
| Карточка вопроса | Кабинет отельера | Причина, способы ответа, следствие |
| Разметка фасадов | Кабинет отельера | Кликабельный силуэт здания |
| Карточка конфликта | Консоль, отельер | Два источника, правило, итог |
| Метка «демо» | Все синтетические данные | Спокойная, но заметная |
| Атрибуция | Под картами и визуализациями | «© OpenStreetMap contributors», «Copernicus DEM», «Open-Meteo» |

## 6. Сценарии для прототипа

Прототип должен проходиться по этим сценариям целиком.

1. **Анна (главный).** `/` → вводит «тихо, закат над морем, без подъёмов, ноябрь, вдвоём» → холст из 5
   чипов → выдача, 6 отелей → открывает первый → ваше окно: этаж 2 → 6, появляется море и точка
   заката → «почему мы так думаем» → бронь Делюкс с запросом «ЮЗ, этаж ≥ 4» → статус.
2. **Подборка.** `/` → «Тишина и горы» → холст заполнен → убирает «горы» → выдача перестраивается.
3. **Неизвестное желание.** На выдаче добавляет «можно с собакой 30 кг» → живое исследование → два
   отеля ответили → карточки обновились.
4. **«Как этот, но тише».** Со страницы отеля → новая выдача с объяснением различий.
5. **Отельер.** `/partner` → вопрос «какие номера на ЮЗ?» → разметка фасада → видно следствие → запрос
   Анны подтверждён.
6. **Консоль: новая характеристика.** «Хинкальная в 10 минутах пешком» → рецепт → пробный прогон → в
   поиске.
7. **Консоль: «построили дом».** Рисуем здание → пересчёт → у отеля пропало море со 2–4 этажей →
   уведомления → выдача Анны изменилась.
8. **Без ключа LLM.** Сценарий 1 проходит, ввод разбирается словарём, объяснения шаблонные.

## 7. Правила контента и данных

- Все цифры в макетах — правдоподобный пример до подключения данных. В прототипе их видно как
  демо-данные, и потом они заменяются расчётом.
- Названия отелей: в прототипе можно использовать реальные названия из OSM только вместе с
  рассчитанными фактами. Пока фактов нет — нейтральные названия-заглушки.
- Синтетика (цены, категории номеров, история пользователя, отзывы) помечена «демо».
- Никаких выдуманных логотипов, отзывов, наград и метрик бизнеса.
- Уверенность: шкала словами «точно» / «скорее да» / «не уверены» / «скорее нет», число по запросу.
- Типографика: «ёлочки», `ё`, неразрывный пробел перед единицами (`60 м`, `16:52`), табличные цифры в
  таблицах и процентах, длинные русские слова не ломают карточки.

## 8. Движение

Движение объясняет причину и следствие, а не украшает. Обязательные моменты:

| Момент | Что объясняет | Подход |
|---|---|---|
| Лендинг → рабочее пространство | «Это один продукт, вы уже внутри» | Shared element: поле → холст, выдача вырастает снизу |
| Правка чипа → перестройка выдачи | Причина и следствие | Перестановка карточек (layout/Flip), смена процентов |
| Слайдер этажа → панорама | Как этаж меняет вид | Плавная интерполяция линии горизонта |
| Даты → солнце | Когда и где закат | Дуга солнца сдвигается, время обновляется |
| Факт → «почему» | Откуда знание | Панель выезжает из факта, с которого открыта |
| Ответ агента или отельера → выдача | Знание добыто сейчас | Подсветка изменившихся строк |
| «Построили дом» → вид пропал | Мир меняется, мы следим | Здание вырастает на карте, сектор моря на панораме закрывается |

Тайминги и правила — по `design-studio` (feedback 100–200 мс, переходы 250–400 мс, stagger ≤ 30 мс).
Для каждого момента нужна версия с `prefers-reduced-motion`.

## 10. Референсы: что искать

**Mobbin, flows:** hotel booking, search with map, travel planning AI, onboarding preferences,

**Mobbin, screens:** map and list split view, filter chips / tags input, search suggestions, AI assistant

**Mobbin, sections (лендинг):** hero with search input, product explanation sections, developer API
