# 06. План исполнения

**Обновлено 27.10.2026.** Решение команды: при планировании **время не ограничиваем**. Мы пишем код с AI
примерно в 10 раз быстрее обычного, поэтому целимся в максимальный объём из
[05 §11](05-concept-and-features.md#11-объём-фундамент-сила-вау). Дедлайн при этом жёсткий:
**тег `submission` до 29.10.2026, 10:00 МСК** — после этого изменения не смотрят.

Команда: **2 человека**, оба фулстек, оба работают с AI. Кто что делает — решим позже, ниже вариант
по умолчанию.

## Принципы

1. **Всегда есть рабочая сквозная версия.** Сначала тонкий вертикальный срез от данных до экрана в
   Docker, потом глубина. Решение, которое не запустилось у жюри с первого раза, уходит в конец списка,
   поэтому сборка с нуля проверяется после каждого крупного шага, а не в последний вечер.
2. **Контракт первым.** Формат данных из [08 §9](08-design-brief.md#9-контракт-данных-для-моков) —
   общий для фронта, бэкенда и дизайн-сессии. Фронт работает на моках этого контракта, бэкенд отдаёт то
   же самое, меняем через один файл.
3. **Глубина важнее ширины.** Шесть характеристик глубоко и с доказательствами лучше двадцати
   поверхностных. Фундамент закрываем целиком до силы, силу — до вау.
4. **Коммитим часто и осмысленно.** Жюри смотрит всю историю репозитория сдачи и спрашивает по коду:
   каждый должен уметь объяснить свою часть.
5. **Без ключа LLM работает всё.** Каждую LLM-функцию сразу делаем с фоллбеком.

## Потоки работ

| Поток | Что делает | Ключевой результат |
|---|---|---|
| **G — Гео и данные** | OSM-выгрузка, DEM, высоты зданий, фасады, горизонт и видимость, солнце, шум, маршруты, климат, векторные тайлы региона для карты | Предрасчёт фактов + функции пересчёта |
| **K — Знания и агенты** | Хранилище фактов (Postgres + PostGIS), реестр характеристик, агенты (исследователь, сверщик, связной с отельером, куратор), симулятор отельера, компилятор новых характеристик, актуализация | API фактов, вопросы и ответы, конфликты, трассы |
| **S — Подбор и API** | Агент намерений (LLM + словарь), профиль вкуса, ранжирование и риск разочарования, объяснения, сравнение, «как этот, но…», REST/OpenAPI, MCP | `/search`, `/hotels/{id}`, MCP-инструменты |
| **F — Интерфейс** | Вход-лендинг, холст, выдача с картой, «Как это будет», бронь, кабинет отельера, консоль, `/developers`. Дизайн — из параллельной сессии | Все сценарии из [08 §6](08-design-brief.md#6-сценарии-для-прототипа) кликаются |
| **P — Качество и сдача** | Эталонная разметка, метрики, README, проверка Docker с нуля, видео, питч | Метрики, README, видео, тег |

### Как поделить на двоих (вариант по умолчанию, решаем позже)

- **Человек 1 — «знания»**: G + K. Всё, что добывает, хранит и проверяет факты.
- **Человек 2 — «продукт»**: S + F, ведёт параллельную дизайн-сессию.
- **P — общий**: эталон размечаем вдвоём, Docker с нуля проверяет тот, кто не трогал последнее
  изменение.
- Точки стыка: контракт данных (принцип 2) и API. Оба держат в голове главный сценарий Анны.

## Порядок сборки

Этапы идут по зависимостям, а не по датам. Внутри этапа потоки работают параллельно.

### Этап 0. Скелет и контракт

- [ ] Скелет репозитория сдачи: `docker-compose.yml` (app + postgis), `Dockerfile` (multi-stage,
      non-root, `linux/amd64`, зафиксированные версии), `/health`, `.env.example`, автоматические
      миграции и сиды. **Сразу проверить `docker compose up --build` с нуля.**
- [ ] Контракт данных и API (08 §9 → OpenAPI). Моки для фронта.
- [ ] Схема БД: hotels, buildings, facades, room_types (демо), characteristics, facts, fact_history,
      evidence, conflicts, questions, answers, agent_runs, users (демо), bookings.
- [ ] Параллельно: дизайн-сессия (гейт 1 — направление).

### Этап 1. Тонкий сквозной срез

- [ ] G: выгрузка OSM по Большому Сочи + тайлы DEM `N43 E039` и `N43 E040`; привязка отелей к зданиям,
      фасады.
- [ ] G: **спайк горизонта** на 3 отелях: море да/нет по фасадам и этажам, проверка глазами (Wikimedia,
      ручные панорамы). Главный технический риск — снимаем первым.
- [ ] K: загрузка фактов с происхождением в БД.
- [ ] S: разбор запроса словарём + ранжирование.
- [ ] F: вход → холст → выдача → страница отеля на реальных (пусть грубых) фактах.
- [ ] **Контрольная точка:** сценарий Анны проходит в Docker с нуля без ключа LLM.

### Этап 2. Фундамент целиком

- [ ] G: все вычисляемые характеристики по всем отелям: вид на море, закат по месяцам, горы, шум день и
      ночь, дорога до пляжа, ночная инфраструктура, климат и вода. Монте-Карло для уверенности.
- [ ] K: сверщик (слияние, конфликты, сроки годности), связной с отельером (ценность вопроса, разбор
      ответа), симулятор отельера со скрытой правдой.
- [ ] S: агент намерений с LLM и фоллбеком, объяснения, риск разочарования.
- [ ] F: «почему мы так думаем», базовый кабинет отельера, состояния экранов.
- [ ] P: эталонная разметка (40–60 отелей × 5–6 характеристик).
- [ ] **Контрольная точка:** фундамент из 05 §11 закрыт, сборка с нуля проходит.

### Этап 3. Сила

- [ ] «Ваше окно» со слайдером этажа и солнцем по датам.
- [ ] Подборки-настроения, помощник запроса, профиль вкуса на синтетической истории.
- [ ] Живое исследование, новая характеристика текстом, добавление отеля вживую.
- [ ] Актуализация «построили дом» с уведомлениями.
- [ ] Сравнение, бронь категории с автозапросом и подтверждением, разметка фасадов, спрос.
- [ ] Консоль: реестр, трассы, конфликты, лента изменений, качество.
- [ ] Hotel Knowledge API + MCP + демо с внешним агентом.
- [ ] **Контрольная точка:** все сценарии из 08 §6 проходят, сборка с нуля проходит.

## Риски и что с ними делать

| Риск | Вероятность | Что делаем |
|---|---|---|
| Не запустится у жюри (сборка, порты, ключи, amd64) | Высокая для всех | Проверка с нуля после каждого этапа; работа без ключа; зафиксированные версии; компактные данные в репозитории |
| Амбициозный объём съест время на сдачу | Высокая | Этап 5 начинается по времени, а не по готовности; вау-фичи только поверх рабочей силы |
| Горизонт считается неверно или медленно | Средняя | Спайк на этапе 1; предрасчёт офлайн; грубая сетка + уточнение рядом |
| Высоты зданий неизвестны (~40%) | Высокая | Оценка с широким разбросом и низкой уверенностью; честный UI; вопрос отельеру |
| Дизайн и бэкенд разъедутся | Средняя | Один контракт данных (08 §9), моки по нему |
| Ключи LLM: жюри не даст | Средняя | Всё работает без ключа; любой OpenAI-совместимый endpoint; опциональная локальная модель |
| Тяжёлые гео-зависимости раздувают образ и сборку | Средняя | Колёса manylinux, без сборки GDAL; гео-предрасчёт вне рантайма |
| Карта зависит от внешних тайлов | Средняя | Векторные тайлы региона (PMTiles) в репозитории или в сидах |
| Нарушение п. 6.5 правил (чужие фото и данные) | Низкая | Только наши визуализации и открытые лицензии с атрибуцией; синтетика с пометкой |
| GitHub Actions в организации не работает | Известно | Проверяем локально |
| Утечка секретов | Низкая | `.env` в `.gitignore`, проверка перед пушем |
| Ресёрч попадёт в репозиторий сдачи | Низкая, но фатально | `docs/research/` и `.private/` живут только в приватном репозитории |
