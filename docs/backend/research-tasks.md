# Задания для ChatGPT и Codex

Сюда попадает всё, что нужно найти в интернете или сгенерировать как справочник или набор для оценки.
Выполняет владелец в ChatGPT (в браузере, с поиском) или в Codex, чтобы не тратить токены сессий и деньги
API (D-27, D-31). Данные региона (здания, дороги, рельеф, климат) сюда не относятся: их получают скрипты
пайплайна, иначе нельзя показать жюри, откуда они взялись.

Как выполнять:

1. Копируем текст задания целиком в новый чат.
2. Ответ сохраняем как есть в `docs/backend/research/<файл из задания>`.
3. Отмечаем строку в таблице ниже: `готово, дд.мм`.
4. Сессия, которая берёт зависимую задачу, проверяет ответ глазами, правит и переносит в `backend/data/…`.

Правила для всех заданий: только открытые источники; Островок, Booking и другие OTA не используем и не
скрапим; у фактов — ссылка и дата; синтетика помечена «демо»; если не уверен — так и пишем, без выдумок.

## R3. Ответы отельеров для оценки разбора

```text
Нужен тестовый набор для разбора ответов отельеров. Отель в Сочи получает вопрос и отвечает в свободной
форме, как менеджер в мессенджере или голосом (расшифровка без знаков препинания). Сделай 30 ответов:
на каждый из шести вопросов пять вариантов — чёткий, расплывчатый, с числами словами, с преувеличением
(например «у нас все номера с видом на море»), голосовой без пунктуации. Для каждого ответа дай ожидаемые
поля по схеме вопроса и оценку однозначности: high, medium или low.

Вопросы и схемы ответа:
1. facade_rooms: «Какие категории номеров выходят на юго-западную сторону (к морю) и с какого этажа?»
   → {facade: SW, room_types: [названия], floor_from: int|null, floor_to: int|null}
2. pets_policy: «Можно ли с собакой 30 кг? Есть ли доплата?»
   → {allowed: bool|null, species: [dog, cat, ...], max_weight_kg: number|null, fee_rub_per_night: number|null, conditions: str|null}
3. soundproofing: «Какие окна в номерах на стороне железной дороги?»
   → {facade: SW|..., soundproof: bool|null, window_type: str|null, room_types: [...]}
4. blackout: «Есть ли в номерах плотные шторы?» → {blackout: bool|null, room_types: [...] | all}
5. step_free и elevator: «Есть ли лифт и ступеньки на входе?»
   → {elevator: bool|null, step_free_entrance: bool|null, notes: str|null}
6. remote_work: «Есть ли в номерах рабочий стол и стабильный Wi-Fi?»
   → {desk: bool|null, wifi_mbps: number|null, room_types: [...]}

Ответ — один блок YAML: список {question_key, answer_text, expected, clarity}.
```

## R4. Словарь «слово → теги OSM»

```text
Нужен словарь «как гость называет место → фильтр тегов OpenStreetMap» для Сочи. Дай 150 видов мест,
которые гости упоминают в запросах про отель: еда (хинкальная, грузинская кухня, шаурма, кофейня, пекарня,
столовая, ресторан у моря, бар, клуб…), магазины (продуктовый, круглосуточный, рынок, винный…), здоровье
(аптека, круглосуточная аптека, детская больница, травмпункт, стоматология), дети (детская площадка,
аквапарк, зоопарк, дельфинарий), животные (ветклиника, площадка для собак, зоомагазин), транспорт
(ж/д станция, остановка, канатная дорога, парковка, зарядка для электромобиля, прокат велосипедов),
отдых (пляж, набережная, парк, смотровая площадка, бассейн, спортзал, спа, теннис, горнолыжный подъёмник)
и всё, что ещё часто спрашивают.

Для каждого вида:
- osm: список альтернатив (между ними ИЛИ), внутри альтернативы теги через И, формат
  {key: value | [values] | "*"};
- name_regex: если вид часто узнаётся только по названию (например «хинкал»);
- coverage_note: насколько полно это размечено в OSM в России: high, medium или low, и почему;
- uncertain: true, если в маппинге не уверен.
Опирайся на OSM Wiki (wiki.openstreetmap.org), теги не выдумывай.

Ответ — один блок YAML: {"хинкальная": {osm: [...], name_regex: "...", coverage_note: "...", uncertain: false}, ...}.
```

Найди в открытых источниках параметры для моделей шума и солнца в Большом Сочи. По каждому пункту дай
