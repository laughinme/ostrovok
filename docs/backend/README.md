# Бэкенд: как работаем

Для любой сессии (Claude, Codex) и любого из нас, кто берёт задачу бэкенда. Бэкенд ведёт владелец
репозитория вместе с параллельными сессиями. Всё, что решено, сделано и запланировано, живёт в этой
папке, чтобы сессии не мешали друг другу и не теряли контекст.

| Файл | Что внутри |
|---|---|
| [`../research/09-backend-architecture.md`](../research/09-backend-architecture.md) | Архитектура, согласована 28.10 |
| [`decisions.md`](decisions.md) | Журнал решений. Если расходится с 09, прав журнал, а 09 надо поправить |
| [`tasks.md`](tasks.md) | Доска задач: статусы, зависимости, кто взял, занятые общие файлы |
| [`progress.md`](progress.md) | Журнал сессий: что сделано, как проверить, грабли, что дальше |
| [`research-tasks.md`](research-tasks.md) | Задания для ChatGPT и Codex: справочники и наборы для оценки |

Папка внутренняя, как `docs/research/`: в репозиторий сдачи её не переносим.

## Начало сессии

1. `CLAUDE.md` в корне: правила проекта и жёсткие требования организаторов.
2. 09: §0 целиком и разделы, которые касаются задачи.
3. `decisions.md` целиком.
4. `tasks.md`: свободные задачи, у которых все зависимости в `done`.
5. Последние 3–5 записей `progress.md`.

## Взять задачу

- Берём задачу в статусе `todo`, у которой все зависимости в `done`. Одна сессия — одна задача.
- Сразу меняем её строку статуса на `в работе · <сессия> · <дд.мм чч:мм МСК>`. Рабочее дерево у сессий общее,
  поэтому отметку видят все сразу; отдельный коммит под неё не делаем, она уходит в git вместе с работой.
- Имя сессии короткое и понятное: `claude-horizon`, `codex-pipeline`.
- Если задача оказалась больше, чем казалось, делим её в tasks.md на подзадачи (`B2.5a`, `B2.5b`).

## Во время работы

- Код по 09 §10 и правилам шаблона: слои, контексты, порты, без God-классов, тесты к каждому сценарию.
- Перед использованием библиотеки сверяем её API через Context7.
- Новое решение (библиотека, формат данных, отступление от 09) сразу дописываем строкой в `decisions.md`.
  Если меняется архитектура, правим и 09.
- Общие файлы меняет одна сессия за раз, занятость отмечаем в разделе «Общие файлы» в tasks.md:
  `backend/pyproject.toml` и `uv.lock`, `backend/migrations/`, `docker-compose.yml`, `compose.dev.yml`,
  `.env.example`, `Makefile`. Новая миграция создаётся только от текущей головы; после неё
  `alembic heads` показывает одну голову.
- Коммитим по ходу работы, как это делал бы аккуратный разработчик: один коммит — одна законченная задача или
  осмысленная часть фичи (обычно несколько сотен строк), без отдельных коммитов под статусы и журналы. Коммиты осмысленные, по-английски, в повелительном наклонении, с областью:
  `backend: add job queue with leases`, `pipeline: fetch OSM buildings`, `docs: record decision D-34`.
  В коммит идут только свои файлы (`git add <пути>`, без `-A` и `commit -a`): в той же папке работают
  другие сессии. Подписей ИИ (Co-Authored-By и подобных) в коммитах нет.
- Перед коммитом кода — `make check`. Пока каркаса нет — `ruff`, `mypy` и `pytest` по своей части.
- Ключи и пароли лежат только в локальном `.env` (он в `.gitignore`). В документы, коммиты, логи, тесты и
  память их не пишем. Ключ для жюри отдельный и уходит через `secrets.env.age` (D-24).
- Бюджет LLM (D-26): тесты сеть не трогают (фейковая модель или PydanticAI `FunctionModel`,
  `ALLOW_MODEL_REQUESTS = False`); реальные вызовы — только `make eval-llm` и короткие ручные проверки, с
  кэшем ответов; по умолчанию дешёвая модель. Пока баланс OpenAI не пополнен (D-25), LLM-путь проверяем
  только тестовыми моделями.
- Справочные данные в интернете сами не ищем: пишем задание в `research-tasks.md`, его выполнит ChatGPT
  или Codex (D-27, D-31). Данные региона получаем только скриптами пайплайна.

## Закончить задачу

- В tasks.md: `done · <сессия> · <время>` и строка `Итог: … (коммит abc1234)`.
- В progress.md — запись по шаблону из его начала.
- Снимаем отметку с общих файлов.
- Не успели доделать — статус `пауза`, в progress.md пишем, где остановились и что дальше.

## Без явного «да» владельца не делаем

- Не пушим в репозиторий сдачи, не переносим туда историю, не ставим тег `submission`. В этот приватный
  репозиторий пушить можно, когда готов рабочий кусок, который стоит выкатить (D-35).
- Не гоняем LLM по всем отелям и не подключаем платные сервисы.
- Не переносим `docs/research/`, `docs/backend/`, `.private/`, `archive/` в репозиторий сдачи.
- Не храним чужие фото и отзывы, не скрапим Островок и OTA.
