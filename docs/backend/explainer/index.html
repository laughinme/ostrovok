Что происходит после «хочу тихо и море»

Бэкенд — один Python-проект. API принимает запросы, отдельный воркер выполняет долгие задачи. PostgreSQL с PostGIS хранит отели, геометрию, факты, очередь и историю; Redis передаёт уведомления и считает лимиты. Next.js показывает результат, nginx объединяет сервисы на порту 8080.

1. Понять запросНамерения → желания, важность, даты, бюджет.
2. Найти знанияФакты для подходящих фасадов, этажей и месяцев.
3. Сравнить номераКод считает соответствие и выбирает лучший вариант.
4. Показать основанияРекомендация номера, компромисс и источники.

POST /api/v1/intents разбирает текст. Режим ?planner=rules быстро показывает предварительные чипы при вводе. POST /api/v1/searches ранжирует варианты; клиент может передать уже разобранные чипы. LLM может переформулировать объяснение, но баллы считает код.

Как устроен балл соответствия

У пожеланий веса 3 («обязательно»), 2 («важно») и 1 («желательно»). Код берёт взвешенное среднее вероятностей и дополнительно снижает результат за слабое выполнение обязательных пожеланий. Если знания нет, для сортировки используется prior, а в интерфейсе остаётся «неизвестно». Варианты сравниваются в совместимой области номера: нельзя сложить море с западной стороны и тишину с восточной в один идеальный номер.

«Риск» — эвристика на основе произведения вероятностей важных пожеланий. Это не измеренная частота разочарований гостей; свойства могут зависеть друг от друга.

Результат «западная сторона, этаж не ниже 4» — просьба к отелю. Наличие свободной категории и выполнение запроса требуют подтверждения. Цены, номера и брони в демо синтетические.

Факт начинается с источника

Открытые данные

OSM даёт здания, дороги и места; Copernicus — рельеф; Open-Meteo — климатические данные. Скрипты готовят компактный регион и готовый слой знаний, который загружается при запуске.

Расчёт

Вид проверяется по геометрии препятствий и рельефа; солнце — по его положению на дату; шум — по модели источников и затухания; путь к пляжу — по пешеходному графу с уклонами и ступенями.

Наблюдение → факт

Наблюдение хранит, кто и что сообщил. Сверщик сопоставляет наблюдения в одной области, учитывает источник, обнаруживает конфликт и создаёт версию факта. Сохраняются доказательство, уверенность и срок актуальности.

Область действия

Фасад × этажи × месяцы × категория номера. Утверждение о нескольких номерах не должно превращаться в обещание для всего отеля.

Что означает уверенность

Для расчётов модель многократно меняет входные данные в пределах погрешности (Монте-Карло). Далее учитывается надёжность источника, объединяются наблюдения, старые сведения теряют уверенность. Отзывы гостей дают бета-обновление. Уверенность расчёта ограничена 0,95: это результат модели, не натурный замер.

Число 0,95 пока нельзя читать как «95 из 100 гостей подтвердят». Для такой калибровки нужен независимый эталон R7, которого сейчас нет. Карта может быть неполной, модель шума приблизительна, климат — не прогноз погоды на конкретный день.

Восемь ролей, один журнал действий

«Агент» здесь означает отдельную роль с целью, разрешёнными инструментами и трассой. Не каждой роли нужна нейросеть.

Агент намерений

Переводит слова гостя в чипы и поездку. LLM понимает свободную речь; без неё работают словарь и правила.

Куратор

Переводит «хинкальная в 10 минутах» в рецепт. Может посмотреть словарь OSM и статистику тегов. Код валидирует рецепт и пробует его на отелях. Новая характеристика остаётся черновиком или предварительной до публикации оператором.

Исследователь

Исполняет рецепт: геометрия, маршрут, места или климат. Получает наблюдения от инструментов. LLM для вычислений не нужна.

Связной

Создаёт вопросы отелю, разбирает ответ в поля. LLM помогает с формулировками и свободным текстом. Неясный ответ требует уточнения; формы обрабатываются правилами.

Сверщик

Объединяет наблюдения, разрешает противоречия по правилам, записывает факты и версии. Не спрашивает LLM, правда ли видно море.

Наблюдатель

Находит отели, затронутые изменением здания или окружения. Ставит пересчёт в очередь; система сообщает об изменённых фактах. Отдельный периодический обход перепроверяет устаревающие сведения.

Подборщик-объяснитель

Код ранжирует варианты. LLM может коротко переформулировать компромисс. Проверка запрещает новые числа, но не доказывает смысловую достоверность каждой фразы — это ограничение текущей реализации.

Симулятор отельера

Демонстрационный заменитель настоящего партнёра: отвечает на основе скрытой демо-правды. LLM добавляет стиль персоны; без неё есть шаблоны. Эти ответы не являются независимыми доказательствами.

Как долгие задачи переживают сбой

API записывает запуск и задачу в PostgreSQL. Воркер забирает задачу с арендой и продлевает её во время работы. После сбоя аренда истечёт и задача сможет повториться. Шаги хранятся в БД; Redis и SSE доставляют уведомления браузеру. Повторная доставка предусмотрена, поэтому операции должны выдерживать повтор.

Что происходит с неизвестным пожеланием

Гость запускает исследование через POST /searches/{id}/wishes, получает runId и наблюдает шаги через GET /runs/{id}/events. Вычислимое пожелание превращается в рецепт. Невычислимое, например условия размещения с собакой, уходит в кабинет отеля. Поиск продолжает работать, пока сведения собираются.

Как выбираем модель

Сравниваем одинаковые задания: 40 запросов, 30 ответов отелей и 15 описаний для Куратора в отложенном наборе. Он синтетический, составлен отдельно от правил. Дополнительно есть набор разработки. Ни один из них не подтверждает реальный вид или шум в отеле.

Что защищает от лишних расходов и сбоев

Кэш разделён по провайдеру, модели, рассуждениям, промптам и схемам. Есть таймаут, лимиты запросов и инструментов на запуск, общий дневной счётчик и выключатель в консоли. При сбое используются правила. Лимит вызовов не равен жёсткому лимиту в долларах; биллинг провайдера проверяется отдельно. В тестах сеть выключена, платные запросы выполняются явной командой оценки.

OpenAI использует Responses API; Vertex Gemini — OpenAI-совместимый Chat Completions и заголовок x-goog-api-key. OpenRouter и российские API в этой сессии не проверены: ключей нет. Доступность из сети жюри без VPN ещё нужно подтвердить.

Реальные запросы и ответы LLM

Это сохранённые вызовы из оценочного прогона, не симуляция кнопок. Вызов новой модели при открытии страницы не происходит.

Что проверено, а что ещё требует данных

  • Автотесты: бизнес-правила, расчёты на контролируемых сценах, авторизация, API, очередь, агенты, кэш и отказ провайдера. Проверяются также типы и границы слоёв.
  • HTTP-сценарий на регионе из 200 отелей: поиск → карточка → доказательство → окно, шум, пляж, климат и день → консоль → MCP.
  • Оценка поисковой выдачи использует фиксированную рубрику команды по рассчитанным фактам. Это проверка согласованности ранжирования, а не независимая оценка реального мира.
  • R7 пока пуст: независимая точность и калибровка уверенности не измерены. Список 40 отелей и готовое задание для поиска источников находятся в R7-request.txt.
  • Холодная сборка без кэша на настоящей x86-машине и доступность провайдера из сети жюри — отдельные проверки. Фронтенд подключает другой участник команды.

Как получить независимый эталон

ChatGPT может собрать ссылки и точные утверждения с официальных сайтов. Затем человек проверяет, действительно ли они подтверждают конкретную категорию, фасад и этаж. «Есть номера с видом на море» не означает «море видно из любого номера». Если область не ясна, метку оставляем неизвестной. В проект переносим ссылки и фактические заметки, без копирования чужих фото.
