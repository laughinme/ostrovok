# R10. Polza.ai: проверка для жюри, 29.10.2026

**Выбор:** Polza.ai, `https://polza.ai/api/v1`, модель `openai/gpt-5.6-luna`,
рассуждения `low` для обычных задач и `medium` для Куратора. Текущий адаптер работает
через Chat Completions без изменений кода. Прямой OpenAI остаётся проверенной альтернативой
для среды с доступом к нему; исходный ключ сохранён только локально.

## Источники и ограничения доступа

- [Официальная страница](https://polza.ai/alternatives): API работает из России напрямую,
  без VPN. Дополнительная прямая проверка ниже подтвердила это для выбранной модели.
- [Документация API](https://github.com/polza-ai/docs/blob/main/api-reference/introduction.mdx):
  OpenAI SDK, `base_url=https://polza.ai/api/v1`, Bearer API key.
- [Responses API](https://github.com/polza-ai/docs/blob/main/api-reference/responses/create.mdx)
  тоже есть, но находится в beta и преобразует запрос в Chat Completions.
  Короткая проверка Responses прошла; приложение использует проверенный Chat Completions.
- Каталог `/models` подтвердил нужный ID, `tools`, structured output и reasoning.
  Ключи не разрешают неофициальных провайдеров (`allowUnofficialProviders=false`).
- Прямой запрос `/models` с `trust_env=False` дал 200, переменных HTTP-прокси нет.
  Первоначальная геопроверка вернула **FR**, но 29.10 выяснилось, что именно её адрес
  маршрутизируется через VPN (`utun7`); по этому ответу нельзя определять маршрут Polza.
  Российский доступ Polza подтверждён отдельным соединением ниже, O3 закрыт.
  Наличие VPN и регион запуска у жюри организаторы по-прежнему не подтвердили.
- На скриншоте кабинета объявлены работы **29.10, 06:00–07:00 МСК**. Проверки ниже
  выполнены около 00:38–00:42 МСК, до этого окна; короткий прогон не гарантирует будущий uptime.

## Полный eval

Исторический прогон до исправления профиля SDK для префикса `openai/` (R11):
фактический reasoning тогда определял провайдер, а не подписанные low/medium.
Свежие результаты с проверенными параметрами — в R11.

```sh
make eval-llm LLM_MODELS=openai/gpt-5.6-luna \
  LLM_EVAL_ARGS='--thinking low --thinking-strong medium --base-url https://polza.ai/api/v1 --key-env POLZA_API_KEY'
```

`POLZA_API_KEY` читается из локального `.env`, в командной строке ключа нет.
[Исходный JSON](../../../backend/data/eval/llm/history/before-polza-profile-fix.openai_gpt-5.6-luna.low+openai_gpt-5.6-luna.medium.5086a6e110.json)
содержит метрики версии 2: откаты на правила исключены.

| Проверка | Разработка | Hold-out | Ответы LLM |
|---|---:|---:|---:|
| Намерения: F1 известных ключей | 0,9730 | 1,0000 | 40/40 + 40/40 |
| Ответы отельера: точность машинных полей | 0,9722 | 0,9403 | 30/30 + 30/30 |
| Куратор: точность метода | 0,8571 | 0,9333 | 21/21 + 15/15 |
| Куратор: точность размеченных параметров | 0,7308 | 0,8929 | те же примеры |

Всего 179 задач LLM, без ошибок провайдера и откатов. Объяснения прошли проверку чисел
в 3/3 случаях. Медиана / p95: намерения 2,82 / 4,73 с; ответы 2,22 / 3,32 с;
Куратор 3,35 / 7,97 с. Настройки тайм-аутов приложения не менялись: 15/30 с.

Для сравнения, предыдущий прямой OpenAI на hold-out: 0,97 / 0,94 / 1,00
для намерений / полей ответов / метода Куратора, также с полным покрытием.
На Polza Куратор ошибся в одном из 15 методов: запрос о доле гор в поле зрения отправил
отельеру вместо `view`. Разница между одиночными прогонами не доказывает превосходство
провайдера. Оснований менять модель или сервис по этому прогону нет.

  16,23 с, финал совпал с результатом инструмента. У этой отдельной проверки бюджет
  9 запросов; рабочий лимит Куратора 8 запросов / 8 инструментов не менялся.
- Native structured output прошёл отдельно от финального output tool.
- Через HTTP приложения с отдельным ключом жюри: `/health` — ok, правила — 118 мс,
  живой LLM — 3540 мс, повтор из кэша — 20 мс. Ответы LLM равны целиком,
  даты 12–15.11.2026, бюджет, гости и район сохранены.
- `make check`: ruff, форматирование, strict mypy, 7 контрактов, **509 passed**.

Счёт Polza за первый eval и короткие проверки: **8,65 ₽**; резерв после завершения — 0.
`costUsd=0.0718` внутри JSON eval — оценка по токенам и тарифам модели,
**не рублёвый счёт Polza**. После проверок баланс 191,35 ₽: ранее включённое владельцем
автопополнение с порогом 100 ₽ добавило ещё 100 ₽; месячный предел автопополнения 1000 ₽.

Ключ жюри отдельный, с лимитом **100 ₽ за всё время**. Денежный стоп проверен:
при временном лимите 0,000001 ₽ API вернул 402 `INSUFFICIENT_BALANCE` до генерации;
после проверки лимит восстановлен до 100 ₽. Этот ключ не содержит доступа к управлению
аккаунтом. Административный MCP-токен хранится отдельно от конфигурации приложения.

## Проверка российского адреса без отключения VPN, 29.10 00:51 МСК

Владелец запретил отключать VPN и затрагивать маршруты Claude. Настройки VPN, прокси
и системные маршруты не менялись. Все операции с сетью, кроме двух платных запросов
модели, были чтением состояния или короткими запросами геосервисов.

1. Исходный маршрут `api.anthropic.com` — `utun7`, `polza.ai` — `en0`.
2. Отдельные запросы `curl --interface en0 --noproxy '*'` к Яндекс Интернетометру
   и `ip.mail.ru` вернули один и тот же внешний IPv4. Яндекс определил Новосибирск;
   явный lookup **этого адреса**, а не адреса текущего запроса, через `api.country.is`
   вернул `RU` и тот же IPv4. Сам адрес в отчёт не включён.
3. Через тот же `en0` выполнены два запроса к Polza с отдельным ключом жюри:
   `openai/gpt-5.6-luna`, reasoning=low, вызов `network_probe`, затем передача результата
   инструмента и финальный JSON. Nonce и значение 37 проверены кодом, оба HTTP 200.
   Вся цепочка — 4854 мс; usage показывает 0,01696127 ₽ за два запроса.
4. Повторная проверка: тот же адрес API Claude и маршрут `utun7`, Polza — `en0`,
   те же процессы VPN и неизменная таблица маршрутов IPv4. VPN оставался включённым.

Существующий SSH-профиль сервера тоже проверен: соединение завершилось тайм-аутом,
команд на сервере не выполнялось. Для итогового подтверждения сервер не потребовался.

[Доказательства без ключей и публичного IP](../../../backend/data/eval/polza-ru-smoke.json).
Проверка подтверждает прямой доступ из России на момент прогона, но не uptime сервиса
