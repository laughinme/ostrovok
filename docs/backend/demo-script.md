# Сценарии для демо-видео (B6.5)

Для команды: кто пишет видео и питч. Стек — `docker compose up --build` (или `make up-native`), всё на
`http://localhost:8080`. Между дублями: консоль → «Сбросить демо» (`POST /api/v1/console/demo/reset`) — знания
возвращаются к сиду, брони, вопросы, поиски и «построенные дома» исчезают. Видео пишем с ключом LLM (разбор и
формулировки живее), но каждый сценарий работает и без него — это стоит сказать в кадре один раз.

Перед записью: `uv run python backend/tests/smoke.py` — все шаги «ok».

## 1. Анна ищет номер (гость, 60–90 с)

1. Роль «Анна». Ввод: «Хочу тихий номер, чтобы видеть закат над морем из окна, до пляжа пешком, 12–15 ноября,
   вдвоём». Чипы появляются на холсте при вводе (агент намерений); видно, что «тихо» — обязательно.
2. Выдача: у первых отелей — какой номер просить («З-сторона · этаж ≥ 7»), строки ✓/⚠ по каждому желанию,
   риск разочарования. Показать отель, где компромисс честный («закат есть, но только с 6-го этажа»).
3. Открыть отель → «Ваше окно»: слайдер этажа, море появляется с нужного этажа, путь солнца 12 ноября и время
   заката. «Почему мы так думаем» у факта: метод, Монте-Карло («видно в 15 из 16 симуляций»), источники, история.
4. «Ваш день» на 12 ноября: пляж (туда 6 мин, обратно 7 и подъём), завтрак, закат, ужин, аптека 24/7.

## 2. Новое желание вживую (Куратор, 40 с)

В той же выдаче добавить «хинкальная в 10 минутах пешком». Лента агента: Куратор не знает такой характеристики
→ проверяет данные OSM (`osm.tag_stats`) → собирает рецепт `poi_nearby` → пробный прогон на 5 отелях →
Исследователь считает для отелей выдачи → выдача перестраивается, у чипа появились ✓/✗. В консоли новая
характеристика видна как «выучено из запросов гостей, ждёт проверки».

## 3. Вопрос отелю (Связной и симулятор, 40 с)

Добавить «можно с собакой 30 кг». Связной отправляет вопрос отелям из выдачи; через 5–30 с демо-отельер отвечает
свободным текстом, ответ разбирается в поля (вид, вес, доплата), выдача меняется. Метка «демо-отельер» видна.

## 4. Конфликт «физика сильнее описания» (отельер, 40 с)

Роль отельера (например, `hotelier_salut`, или любой отель из `/console/conflicts`). В кабинете: отель заявил
«вид на море из всех номеров», расчёт видит море только с одной стороны и с N-го этажа — конфликт, правило
`physics`, точечный вопрос «Какие категории номеров выходят на юго-западную сторону?». Ответить разметкой
фасадов → рекомендация номера в выдаче гостя меняется на «подтверждено отелем».

## 5. Построили дом (Наблюдатель, 30 с)

Консоль → «Изменения мира» → добавить 9-этажный дом в 40 м перед фасадом отеля у моря. Наблюдатель находит отели
в радиусе влияния, пересчитывает вид, закат и шум; в ленте — что изменилось и у кого; у отельера — уведомление,
у гостя с бронью — «обещанный вид изменился, предлагаем этаж выше». Откатить изменение.

## 6. Новая характеристика из консоли (оператор, 30 с)

Консоль → «Новая характеристика»: «круглосуточная аптека в 500 метрах». Черновик рецепта, пробный прогон,
«Опубликовать» → расчёт по 200 отелям, покрытие в реестре растёт, поиск сразу понимает «аптека ночью».

## 7. Качество и переиспользуемость (оператор, 20 с)

Консоль → «Качество»: точность разбора запросов и ответов, nDCG поиска, покрытие. «Для разработчиков»: тот же
слой знаний через REST и MCP — внешний агент (Claude) находит номер с закатом в ноябре.

## Что сказать словами

- LLM здесь переводчик и компилятор: факты дают расчёты по открытым данным и отельеры; без ключа всё работает.
- Новая характеристика — данные (рецепт), а не код; стоимость LLM растёт с числом характеристик, а не отелей.
- Данные реальные (OSM, Copernicus, Open-Meteo), синтетика (цены, ответы отельеров) помечена «демо».
