# Журнал решений бэкенда

Новые решения дописываем вниз со следующим номером. Отменённое не удаляем: пишем новое решение «заменяет
D-NN» и помечаем старое `(заменено D-MM)`. Подробности архитектуры — в
[09](../research/09-backend-architecture.md).

## Архитектура (согласована 28.10)

| № | Решение | Почему | Отвергли |
|---|---|---|---|
| D-01 | Модульный монолит: API и воркер из одного образа, PostgreSQL + PostGIS, Redis, Next.js, шлюз nginx на 8080 | Один регион, запуск у жюри с первого раза; границы модулей держит линтер | Микросервисы |
| D-02 | Основа — `~/Code/python/Monolith-backend-template` с переработкой по 09 §10.1: убираем S3, аватары и админку; outbox превращаем в очередь с арендой; добавляем PostGIS, контексты и рантайм агентов | Каркас готов и покрыт тестами | Писать с нуля; брать шаблон как есть |
| D-03 | LLM — переводчик и компилятор. Факты дают только инструменты и отельер; объяснения LLM проверяет код (только переданные факты и их числа) | Требование кейса; стоимость растёт с числом характеристик, а не отелей | LLM как источник фактов |
| D-04 | Агенты: Исследователь, Куратор, Связной, Сверщик, Наблюдатель, Агент намерений, Подборщик-объяснитель и симулятор отельера. У каждого планировщик LLM или правила, след шагов одинаковый | Работает без ключа, агентность видна | Один свободный агент на всё |
| D-05 | Знания: наблюдения → Сверщик → факты, версии, конфликты. Область факта: фасад × этажи × месяцы × категории номеров; фасады — 8 румбов | Источник, уверенность, дата и противоречия следуют из модели | Флаги на уровне отеля |
| D-06 | Расширяемость: закрытый набор методов (`view`, `sun_event`, `noise`, `walk_to`, `poi_nearby`, `area_stat`, `climate`, `ask_hotelier`, `derived`). Характеристика — данные, новый метод — код с тестами | Рецепт можно проверить, протестировать и объяснить | Произвольный граф вызовов, который пишет LLM |
| D-07 | Уверенность: Монте-Карло (50 прогонов офлайн, 16 вживую), лог-шансы с надёжностью источника, затухание после 80 % срока, бета-обновление по отзывам, калибровка по эталону, подписи из 08 §7 | Число уверенности имеет смысл и проверяется | Уверенность на глаз |
| D-08 | Четыре контура: предзаполнение, живое исследование, актуализация, чтение. Чтение не ждёт агентов | Быстрый поиск без гонок | Всё синхронно в запросе |
| D-09 | Очередь задач в Postgres с арендой (`SKIP LOCKED`, `dedupe_key`, `available_at`), воркер — отдельный процесс; шаги агентов в БД, в браузер по SSE через Redis pub/sub; источник правды — БД | Ничего не теряется, без брокеров | Celery и RabbitMQ; фоновые задачи внутри API |
| D-10 | LLM через PydanticAI за портом `LanguageModel`: любой OpenAI-совместимый endpoint. У каждого LLM-порта запасная реализация на правилах; предохранитель; кэш ответов | Ключ не гарантирован, провайдеры бывают недоступны | Один зашитый провайдер; свой HTTP-клиент |
| D-11 | Гео: тяжёлое считаем офлайн (Монте-Карло, граф), лёгкое вживую теми же функциями. В рантайме нет GDAL: рельеф хранится numpy-массивом | Воспроизводимость и быстрый старт | Считать всё на старте; GDAL в образе |
| D-12 | Маршруты: свой пешеходный граф OSM с высотами (scipy), Тоблер, ступени, переходы, профиль «коляска»; закрыт портом `Router` | Свои веса, мало данных | OSRM, Valhalla |
| D-13 | API: REST `/api/v1` с OpenAPI, SSE, MCP на `/mcp` (MCP SDK 2.x, `MCPServer`, монтируется в FastAPI) | Один слой знаний для всех клиентов | GraphQL |
| D-14 | Качество: эталон, точность, калибровка, покрытие, доля вопросов отельеру, точность разбора, nDCG; `make eval` и страница качества | Доп. задача 5 | — |
| D-15 | Контроль архитектуры: ruff, mypy strict, import-linter (слои и контексты), тесты на настоящем PostGIS; всё в `make check` | Поддерживаемость проверяет машина | — |
| D-16 | Авторизация: JWT из шаблона и демо-вход по персоне (гость, отельер, оператор). Отельер видит только свои отели | Жюри проходит все роли без регистрации | Без авторизации; роль в заголовке |
| D-17 | Данные в `backend/data/`: CSV.gz с WKB, npy, npz, JSONL.gz; всего меньше 60 МБ, каждый файл меньше 50 МБ, без Git LFS; загрузка через `COPY`; сид идемпотентный по версии данных | Быстрый старт у жюри | GeoParquet в рантайме; LFS |
| D-18 | Настройки разработки — `compose.dev.yml` и `make dev`, а не `docker-compose.override.yml` | `docker compose up` у жюри сам подхватит override | — |
| D-19 | Шлюз nginx-unprivileged на 8080: `/` → фронт, `/api` и `/mcp` → бэкенд (SSE без буферизации), `/health` → бэкенд | Правило 8080, один origin | Next.js rewrites |
