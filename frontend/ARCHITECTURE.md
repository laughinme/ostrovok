# Архитектура фронтенда

Next.js App Router + React + TypeScript (`strict`) + TanStack Query v5.

## Маршруты и слои

```text
app/                      Next.js: URL, layouts, metadata, loading/error, Route Handlers
pages/README.md           резервирует каталог Pages Router (маршрутов в нём нет)
src/
  app/                    провайдеры приложения и глобальные стили
  pages/                  композиция экранов: search, hotel, compare, book, trip, ...
  widgets/                hotel-card, hotel-evidence, site-chrome
  features/               search-hotels, select-hotels, landing-variants
  entities/               hotel (модель, queries, демо-источник), intent (желания)
  shared/                 HTTP, QueryClient, базовые типы, UI, карты, SVG, форматирование
```

Корневой `app/` — адаптер Next.js. Бизнес-код находится в `src/`.
Каталог `pages/` в корне нужен, чтобы Next.js не принимал FSD-слой `src/pages/` за старый Pages Router.
В `app/(discovery)/layout.tsx` живёт общий экран главной и выдачи: переход `/` → `/search` сохраняет
процесс подбора, таймеры и анимацию. Остальные маршруты имеют собственные `page.tsx`.

Зависимости направлены вниз: `app → pages → widgets → features → entities → shared`.
Соседние слайсы одного слоя независимы. Внешние импорты слайса идут через его `index.ts`;
внутри слайса разрешены внутренние импорты. Сегменты `shared` и `app` не являются слайсами.
Серверные Route Handlers используют отдельный публичный вход `entities/hotel/server.ts` с `server-only`,
чтобы демо-каталог не попадал в клиентский JavaScript.

`npm run lint:architecture` проверяет направления зависимостей, независимость слайсов и публичные входы.
Эта проверка входит в `npm run lint` и `npm run check`.

## Данные и состояние

- `entities/hotel/model/types.ts` — контракт отеля, номеров и фактов. Его продуктовый источник:
  `../docs/research/08-design-brief.md`, §9.
- `entities/hotel/api/queries.ts` — ключи и функции запросов TanStack Query: список и детали.
- `shared/api` — HTTP transport, HTTP-ошибки и отмена через `AbortSignal`.
- QueryClient отдельный при серверном рендеринге и общий для вкладки браузера. Свежесть — 60 секунд;
  сетевые ошибки и 5xx повторяются до двух раз, 4xx автоматически не повторяются.
- `features/search-hotels` хранит текст, важность желаний и известные характеристики, рассчитывает совпадение.
- `features/select-hotels` хранит сравнение и избранное. Оба состояния живут между переходами,
  но сбрасываются после полной перезагрузки, как в исходном прототипе.
- Экраны с данными показывают загрузку, ошибку с повтором и отсутствие отеля. Неизвестный ID не заменяется первым отелем.

Layout, метаданные и HTTP-обработчики работают на сервере. Интерактивные экраны — Client Components;
данные загружаются в браузере через TanStack Query. Серверного prefetch/dehydrate пока нет.
DOM/SVG и MapLibre инициализируются в эффектах; Vite-специфичный импорт worker удалён, Next.js собирает worker из пакета.

## Подключение бэкенда

Без переменных окружения клиент обращается к встроенным демо-обработчикам:

| Запрос | Ответ |
|---|---|
| `GET /api/hotels` | `Hotel[]` |
| `GET /api/hotels/:id` | `Hotel`, для неизвестного ID — HTTP 404 |
| `GET /health` | `{"status":"ok"}` |

Для внешнего API скопируйте `.env.example` в `.env.local` и замените `NEXT_PUBLIC_API_BASE_URL` на базовый URL,
например `http://localhost:8000/api`. При такой настройке ожидаются `GET /hotels` и `GET /hotels/:id`
относительно этого URL и указанные выше формы JSON. Для другого origin бэкенд должен разрешить CORS.
Переменная публичная, встраивается при сборке; после изменения нужна пересборка/перезапуск.
Секреты в `NEXT_PUBLIC_*` хранить нельзя.

Это текущий контракт демо-адаптера, не утверждённый контракт будущего бэкенда. Когда появится OpenAPI,
согласуйте типы и замените transport/queries в `entities/hotel`, сохраняя UI экранов.
Тела JSON пока типизированы TypeScript без runtime-валидации; валидацию внешнего контракта следует добавить при интеграции.
Бронь, подтверждения, исследование агентами, кабинет отельера и консоль по-прежнему имитируют изменения локально.
Запросы на запись и реальная оплата не реализованы.
