# Луч — frontend

React, TypeScript, TanStack Start, Tailwind CSS и Zustand. Поиск, карточки отелей,
сравнение и кабинет отельера подключены к FastAPI через `/api/v1`.
По умолчанию запросы проксируются на `https://okno-api.fly.dev`;
`BACKEND_URL=http://127.0.0.1:8000 npm run dev` переключает на локальный API.
Цены, рейтинги, категории номеров и ответы демо-отельера синтетические.
Для проверки дизайна без расходов LLM выберите «Демо» в шапке. Поиск, каталог,
сравнение, доказательства, заявка и ответы отельера имитируются локально с задержкой;
запросов к API нет, в том числе при обновлении страницы. Режим сохраняется в cookie.
«Гость» или «Отельер» возвращают обычный API. Избранное двух режимов раздельное.
Оставшаяся работа по обеим сторонам описана в [`../DIFF.md`](../DIFF.md).

Главная объединяет текущий первый экран приложения с обновлённым лендингом:
фотоподборки, 3D-отель с выбором этажа и фасада, анимированные схемы доказательств,
иллюстрации и финальный блок с прилётом самолёта. Общая шапка, поле запроса,
городской фон и навигация остаются компонентами основного фронта.
Три варианта A/B/C сохранены: обновлённый салатовый C по умолчанию,
переключатель через `/?variants=1`. Поиск с главной
ведёт в прежний `/search?q=…` и затем в `/results`. Стили лендинга ограничены
`.landing-page`; остальные страницы, данные и пользовательские правки сохранены.
Исходная версия Next.js находится в `archive/frontend-next`.

Секции лендинга находятся в `src/pages/home/ui/showcase`, их стили ограничены
`.landing-showcase` внутри `.landing-page`. Three.js загружается при приближении
к 3D-сцене; без WebGL остаётся схема отеля. Анимации останавливаются вне экрана,
поддерживают reduced motion и очищаются при переходе на другую страницу.
Отдельный прототип удалён после интеграции. Все изменения главной делаются
в `frontend/`; история визуальных проверок — в `../design/landing-verification.md`.

## Запуск

Нужны Node.js 22.12+ и npm. Из корня репозитория:

```sh
cd frontend
npm ci
npm run dev
```

Приложение доступно по адресу http://localhost:5173.

```sh
npm run check
npm run build
npm start
```

`npm run check` проверяет ESLint, границы FSD, отсутствие комментариев, типы,
тесты и production-сборку. `npm start` запускает готовую сборку на
http://localhost:3000; порт меняется переменной `PORT`.

## Архитектура

Зависимости направлены вниз: `app → pages → widgets → features → entities → shared`.
Слайсы одного слоя независимы. Внешний код обращается к слайсу через его `index.ts`.
В `app` и `shared` публичные API организованы по сегментам. Статические файлы
из `shared/assets` импортируются напрямую.

| Слой       | Ответственность                                      | Содержимое                                                                                                        |
| ---------- | ---------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| `app`      | Инициализация, провайдеры, маршруты, стили, оболочка | `router`, `routes`, `providers`, `styles`, `ui`                                                                   |
| `pages`    | Композиция экранов из виджетов, функций и сущностей  | `home`, `search`, `results`, `hotel`, `compare`, `trip`, `partner`                                                        |
| `widgets`  | Завершённые блоки интерфейса                         | `site-header`, `greeting`, `hotel-map`, `hotel-result-card`, `hotel-gallery`, `hotel-insights`, `search-progress` |
| `features` | Действия пользователя и их состояние                 | `hotel-search`, `compare-hotels`, `manage-hotel-profile`                                                          |
| `entities` | Модель отеля, каталог и представление характеристик  | `hotel/model`, `hotel/api`, `hotel/config`, `hotel/ui`                                                            |
| `shared`   | Универсальные компоненты, утилиты и ресурсы          | `ui`, `lib`, `assets`                                                                                             |

`features/hotel-search` отправляет текст, критерии и бюджет серверу;
ранжирование выполняет backend. `entities/hotel` адаптирует API-каталог к UI;
`shared/api` содержит HTTP-клиент и типы из `openapi.json`. `features/compare-hotels` хранит до трёх выбранных отелей.
`features/favorite-hotels` синхронизирует избранное между выдачей и страницей
отеля и сохраняет его в localStorage. Карточки выдачи позволяют листать
фотографии стрелками, клавишами и горизонтальным свайпом.
`features/manage-hotel-profile` управляет вопросами агента, ответами отельера,
подтверждением фактов и историей изменений.

Маршруты находятся в `src/app/routes` и передают страницам параметры URL и
данные загрузчиков. Страницы не импортируют маршруты или другие модули `app`.
Кэш Query создаётся один раз на экземпляр приложения: данные свежие 5 минут и остаются
в памяти 30 минут после ухода со страницы. Запросы с одинаковым ключом используют один результат.
После устаревания или явной инвалидации обновление идёт в фоне, с прежними данными на экране.
Смена режима «Демо / Гость / Отельер» очищает кэш; между SSR-запросами данные не разделяются.
Фильтры поиска и сравнения сохраняются в памяти, шапка возвращает к последнему запросу подбора.
`keepPreviousData` удерживает выдачу и пьедесталы при изменении критериев и бюджета.

Общий экран загрузки (`app/ui/loading-overlay.tsx`) использует `widgets/search-progress`:
белый самолёт на синем фоне перед векторной Землёй. Он появляется только при отсутствии данных:
`RequestState` регистрирует ожидание через `LoadingSignal`; Router и отложенные карты используют
его в fallback. Фоновый refetch и мутации не открывают полноэкранную сцену. Сохранения показывают
локальное состояние кнопки. Для самостоятельной блокирующей операции есть
`shared/lib/beginLoadingTask`: возвращаемый cleanup вызывается после успеха, ошибки или отмены.
Фон блокируется через `inert`, фокус и прокрутка восстанавливаются при закрытии.

Поиск `/search` заранее загружает намерение, каталог и выдачу и переходит на `/results`
после их завершения. При повторном запросе используются кэш и сохранённые фильтры, без анимации.
Порог появления экрана — 120 ms, для pending Router — ещё 120 ms; минимального времени показа нет.
Пока работа продолжается, самолёт повторяет прямой пролёт циклом 1,3 s, Земля вращается,
индикатор показывает неопределённую загрузку. После готовности — быстрый финиш 180 ms.
При reduced motion сцена статична. После ошибок первой загрузки доступен повтор запроса.
Карточка отеля также читает Query: устаревший кэш возвращается сразу, фоновый ответ обновляет страницу.
Панорама и самолёт сохраняют текущий стиль, WebGL на экране загрузки не используется.

Карта подбора использует MapLibre GL и подложку OpenFreeMap Liberty, как в
`frontend-3`. Она загружается через `lazy` за `ClientOnly`, сохраняет размеры
исходного блока и оформление плашек отелей. У демо-отелей заданы условные
координаты в соответствующих районах; это не адреса реальных объектов.

Детальная страница `/hotel/$id` перенесена из `frontend-3`: фотомозаика,
интерактивная панорама по этажам и фасадам, шум по сторонам, окрестности,
номера с тарифами и панели доказательств. Идентификаторы, фото, цены и факты
берутся из основного каталога через адаптер `pages/hotel/model/hotel-details.ts`.
Стили ограничены `.hotel-detail`. Геометрия, схема пешего пути, климат,
категории номеров и тарифные условия демонстрационные. Форма заявки сохраняет демо-бронь на сервере с ID номера и тарифа;
ответ отеля симулируется, оплата не списывается. Геовизуализации, которым
ещё требуется подключение к расчётам, перечислены в `DIFF.md`.

## Мои поездки

`/trips` восстанавливает страницу из прежнего `frontend-3`, сохранённую в
`archive/frontend-next/src/pages/trip`: посадочный билет, самолёт, перфорация,
синий корешок, даты, панорама окна и штрихкод. Ссылка находится в общей шапке;
прежний `/trips/mayak` перенаправляет на `/trips`.

Перенесены обе вкладки: «До поездки» с ожиданиями и «После поездки» с ответами
на три вопроса. Как в исходной версии, используется сохранённый пример поездки
в «Маяк» 10–15 ноября и имитация подтверждения через 2,5 s. Данные находятся
в `pages/trip/model/trip.ts`; страница пока не читает серверные брони и не
отправляет ответы в API. Панорама общая со страницей отеля (`shared/ui/panorama.tsx`,
`shared/lib/panorama.ts`), стили и переменные билета изолированы в `.trips-screen`.

## Проверки

```sh
npm run lint
npm run typecheck
npm test
npm run test:watch
npm run check:architecture
npm run check:comments
```

Проверка архитектуры анализирует обычные, относительные и динамические импорты.
Она запрещает зависимости от верхних слоёв, соседних слайсов и внутренних файлов
чужого слайса. Проверка комментариев использует синтаксические анализаторы
TypeScript/JSX и CSS: строки и URL комментариями не считаются.

Тесты находятся рядом с моделями и в `tests`. Они проверяют подбор отелей,
состояние сравнения, маршруты и сами правила проверки исходников.

## Генерируемые файлы

TanStack создаёт `.tanstack/route-tree.gen.ts`. Этот кэш исключён из Git и
форматирования. `pretest` и `pretypecheck` автоматически генерируют дерево
маршрутов, поэтому тесты и проверка типов работают после чистой установки.
При необходимости его можно обновить отдельно:

```sh
npm run routes:generate
```

Исходники проекта не содержат комментариев. Объяснения структуры и соглашений
хранятся в этой документации и `AGENTS.md`.

## Vercel

При `VERCEL=1` Nitro собирает Build Output API в `.vercel/output`. Локальная
сборка использует `node-server`. `vercel.json` переопределяет прежний Next.js
framework проекта; workflow продолжает собирать каталог `frontend`.

## API и Docker

Браузер обращается к `/api/v1` на том же origin; Nitro проксирует запросы,
включая авторизацию. `BACKEND_URL` задаёт адрес API при сборке; то же значение
нужно при запуске для SSR. В Docker используется `http://backend:8000`.
Корневой `docker-compose.yml` публикует приложение на 8080 через gateway.

Карточка принимает UUID бэкенда; `sid` в URL сохраняет серверный поиск,
рекомендованный номер, даты и гостей для заявки. `entities/session` получает
отдельные токены демо-гостя и отельера в памяти вкладки. После перезагрузки
демо-вход повторяется; полноценный пользовательский вход пока не подключён.

Типы контракта сохранены в `src/shared/api/schema.d.ts`. Обновление:

```sh
make openapi
cd frontend
node scripts/generate-api.mjs
```

Генератор закреплён на `openapi-typescript@7.10.1`, удаляет комментарии
для соблюдения правил исходников и форматирует результат.

Детальная страница отеля разделяет фотогалерею и расчётные схемы. Источники и материалы
проверки доступны в панели факта; комнаты и тарифы используют серверные идентификаторы.
Страница «Мои поездки» — компактные демонстрационные билеты: в демо три статуса,
в обычном режиме один прежний пример «Маяк». Это локальные примеры, не список реальных броней.
Кабинет отельера открывается из переключателя ролей, с сохранением активного демо-режима.
