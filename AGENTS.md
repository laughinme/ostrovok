# Инструкции для агента

Основные правила проекта лежат в [CLAUDE.md](CLAUDE.md) (они не привязаны к Claude, читай их целиком перед работой).

## Подготовка и поддержка защиты

- Для вопросов жюри сначала используй [контекст текущего кода](docs/research/11-live-code-context.md): в начале — готовые короткие ответы, дальше — потоки данных, ограничения и карта файлов. Прочитай один раз в начале подготовки; повторно исследуй только детали, которых там нет, или изменившийся код.
- На «Жюри: …» отвечай сразу готовой устной фразой в 1–3 предложениях; на вопрос о коде добавляй файл и функцию. Не обещай задержку меньше секунды и не подменяй неизвестные факты догадками.
- Для объяснений участнику без опыта React используй [пособие по фронтенду](docs/research/12-frontend-defense.md). Оба документа внутренние: в репозиторий организаторов их не переносим.

## Бэкенд

- Порядок работы параллельных сессий, решения, задачи и журнал — в [docs/backend/README.md](docs/backend/README.md).
- Коммиты без подписей ИИ, в коммит только свои файлы.

## Дизайн-работа

- Любую визуальную задачу (экран, лендинг, анимация, критика, правки `DESIGN.md`) начинай со скилла `design-studio`
  (`$design-studio`). Не стоит — спроси у владельца архив `design-studio` (в репозитории его нет) и запусти `bash design-studio/install.sh`.
- Команды Impeccable: `$impeccable critique`, `polish`, `audit`, `animate`, `harden`.
- Без просмотра результата глазами «готово» не говорим: скриншоты 1440 и 390, для скролла — скрипт из скилла.

## Коммиты

- После каждого завершённого запроса пользователя делать коммит с изменениями этого запроса.
- Codex по умолчанию работает в `main`: после завершения запроса сразу выполняет `git push origin main`, затем `git fetch origin`, без дополнительного подтверждения пользователя. Другое поведение — только по прямому указанию пользователя.
- Уже накопленные изменения можно включать в серию только по прямому поручению пользователя.
