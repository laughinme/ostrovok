# О!кно

**Островок знает о номере больше, чем его карточка, — и может это доказать.**

Команда **chupapis**, трек «О!дин шаг до идеального отеля», Ostrovok Hackathon 2026.

О!кно — слой знаний об отелях Большого Сочи и агенты, которые его наполняют. Система считает то, чего нет в
карточке отеля: видно ли море из окна конкретной стороны и этажа, садится ли солнце в море в ноябре, тихо ли
ночью, сколько идти до пляжа и обратно в гору, есть ли рядом аптека, которая работает ночью. Каждый факт
хранится с областью действия (фасад × этажи × месяцы), источником, уверенностью, датой и доказательством, а
гость ищет отель своими словами и получает не «отель с видом», а номер, который стоит попросить.

- **200 реальных отелей** Большого Сочи (центр, Хоста, Адлер, Сириус, Красная Поляна) из OpenStreetMap.
- **Знания считаются из открытых данных**: OSM (здания, дороги, ж/д, объекты, берег), рельеф Copernicus DEM,
  климат Open-Meteo. Горизонт из окна с Монте-Карло, траектория солнца, модель шума, пешеходный граф с уклоном
  по Тоблеру.
- **Агенты видимо добывают знание**: Исследователь, Куратор (учит систему новой характеристике по тексту),
  Связной (вопросы отельеру и разбор ответов), Сверщик (сливает источники и разбирает конфликты), Наблюдатель
  (реагирует на «построили дом»), агент намерений и симулятор отельера. У каждого агента два планировщика:
  LLM и правила; шаги пишутся в трассу и видны в интерфейсе.
- **Работает без ключа LLM.** С ключом система лучше понимает свободный текст; без него всё то же самое
  делают правила, и в трассе это видно.

Демо-видео: _ссылка появится перед сдачей_.

## Быстрый старт

Нужен только Docker (Docker Desktop или Docker Engine с Compose v2).

```sh
git clone https://github.com/ostrovok-hackathon-2026/chupapis.git
cd chupapis
cp .env.example .env
docker compose up --build
```

Через несколько минут открывается **http://localhost:8080**. Первая сборка занимает 4–6 минут (дольше всего
собирается фронтенд), старт после сборки — меньше минуты: миграции, ключи и демо-данные загружает сервис
`init`, вручную ничего делать не нужно.

| Адрес | Что там |
|---|---|
| `http://localhost:8080/` | Приложение: гость, кабинет отельера, консоль знаний |
| `http://localhost:8080/health` | `{"status":"ok"}` |
| `http://localhost:8080/api/docs` | OpenAPI (Swagger UI) всего REST API |
| `http://localhost:8080/mcp` | MCP-сервер: знания об отелях для внешних агентов |

Остановить: `docker compose down`. Начать с чистой базы: `docker compose down -v`.

### С ключом LLM

Подходит любой OpenAI-совместимый endpoint (OpenAI, Gemini, OpenRouter, DeepSeek, локальная модель). Укажите в
`.env`:

```sh
LLM_BASE_URL=https://api.openai.com/v1
LLM_API_KEY=...
LLM_MODEL=gpt-5.4-mini
```

Ключ для жюри зашифрован публичным ключом организаторов в `secrets.env.age`:
`age -d -i <ваш ключ> secrets.env.age > .env`. Провайдер и модель для этого ключа указаны в начале файла после
расшифровки. Без ключа и при недоступности провайдера (ошибка, тайм-аут, суточный лимит) все агенты работают
по правилам; режим можно выключить и в консоли («Настройки → LLM»).

### С локальной моделью

Без внешнего API: `docker compose --profile local-llm up --build`, затем
`docker compose exec ollama ollama pull qwen2.5:3b` и в `.env` — `LLM_BASE_URL=http://ollama:11434/v1`,
`LLM_API_KEY=ollama`, `LLM_MODEL=qwen2.5:3b`. Модель скачивается отдельно и в репозиторий не входит.

### Демо-роли

Регистрация не нужна: в интерфейсе есть переключатель ролей. Через API — `POST /api/v1/auth/demo`
с `{"persona": "..."}`:

| Персона | Роль | Что видит |
|---|---|---|
| `guest_anna` | Гость | Поиск, страница отеля, бронь, поездка, профиль вкуса (демо-история) |
| `guest_mark` | Гость | То же, без истории |
| `hotelier_salut`, `hotelier_marriott`, `hotelier_imeretinsky` | Отельер | Кабинет своего отеля: факты, конфликты, вопросы, разметка фасадов, запросы гостей |
| `operator` | Оператор Островка | Консоль: реестр характеристик, трассы агентов, конфликты, изменения мира, качество |

## Что попробовать

1. **Найти номер словами**: «тихий номер с видом на море и закатом, 12–15 ноября, вдвоём». В выдаче для каждого
   отеля — какой номер просить («ЮЗ-сторона, этаж ≥ 4»), вердикт по каждому желанию и честный компромисс.
2. **«Почему мы так думаем»**: у любого факта — метод, источники, доказательство (панорама окна, схема шума,
   профиль маршрута), история и уверенность.
3. **Неизвестное желание**: добавьте «хинкальная в 10 минутах пешком». Куратор научит систему новой
   характеристике (рецепт из объектов OSM), проверит её на пяти отелях, Исследователь посчитает её для выдачи —
   ход агентов виден вживую.
4. **Вопрос отелю**: «можно ли с собакой 30 кг» — Связной спрашивает отели, симулятор отельера отвечает через
   5–30 секунд, ответ разбирается в поля и меняет выдачу.
5. **Конфликт**: отель заявляет «вид на море из всех номеров», расчёт видит море только с одной стороны —
   конфликт с правилом «физика сильнее описания» в кабинете отельера и в консоли.
6. **«Построили дом»**: в консоли добавьте здание рядом с отелем — Наблюдатель найдёт затронутые отели и
   пересчитает вид, закат и шум; изменения попадут в ленту и уведомления.
7. **Ваш день** у отеля: пляж, завтрак, закат, ужин и аптека в выбранную дату — с маршрутами и подъёмами.

## Как устроено

Подробно — [backend/ARCHITECTURE.md](backend/ARCHITECTURE.md).

```text
gateway (nginx, :8080) ─┬─ /            → frontend (Next.js)
                        ├─ /api, /mcp   → backend (FastAPI)
                        └─ /health      → backend
backend, worker         один образ: API и воркер агентов (очередь задач в PostgreSQL)
init                    миграции → ключи JWT → демо-данные (один раз при старте)
db                      PostgreSQL 17 + PostGIS          redis   события для SSE, лимиты
```

- **LLM — переводчик и компилятор, а не источник фактов.** Она разбирает текст гостя, ответы отельеров и
  описание новой характеристики; факты дают только расчёты по открытым данным и отельеры. Объяснения LLM может
  перефразировать только из переданных ей фактов.
- **Расширяемость:** характеристика — запись в реестре с рецептом из закрытого набора методов (`view`,
  `sun_event`, `noise`, `walk_to`, `poi_nearby`, `area_stat`, `climate`, `ask_hotelier`, `derived`). Новая
  характеристика — данные, новый метод — код с тестами.
- **Достоверность:** наблюдения разных источников сливаются в лог-шансах с надёжностью источника, уверенность
  затухает к сроку годности, конфликты разрешаются правилом характеристики, отзывы гостей обновляют уверенность.
- **Код:** модульный монолит, слои `api → service → domain` с адаптерами `db` и `infra`; границы проверяет
  import-linter, типы — mypy strict, поведение — unit и интеграционные тесты на настоящем PostGIS.

## Данные

Демо-данные лежат в репозитории (`backend/data/`, ~30 МБ) и загружаются автоматически. Как они получены —
[backend/data/MANIFEST.md](backend/data/MANIFEST.md); повторить: `make data` (выгрузка и подготовка) и
`make collect` (агенты собирают знания), затем `make export-seed`.

| Данные | Источник | Лицензия |
|---|---|---|
| Отели, здания, дороги, ж/д, объекты, берег | © OpenStreetMap contributors (выгрузка Geofabrik) | ODbL 1.0 |
| Рельеф | Copernicus DEM GLO-30, © DLR e.V., Airbus | Copernicus DEM licence |
| Климат и температура моря | Open-Meteo.com (Historical Weather, Marine) | CC BY 4.0 |
| Номера, цены, рейтинги, ответы отельеров, история гостя | синтетика, помечена в интерфейсе «демо» | — |

Реальных фотографий отелей, чужих отзывов и данных Островка в проекте нет.

## Переменные окружения

Все переменные с безопасными значениями по умолчанию — в [.env.example](.env.example).

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL` | пусто | OpenAI-совместимый LLM; пусто — режим правил |
| `LLM_MODEL_STRONG` | пусто | Модель для Куратора (иначе `LLM_MODEL`) |
| `LLM_TIMEOUT_SEC` | `15` | Тайм-аут вызова LLM |
| `LLM_MODE` | `auto` | `off` — только правила |
| `LLM_DAILY_CALL_LIMIT` | `300` | Суточный лимит платных вызовов |
| `HOTELIER_SIMULATOR`, `SIMULATOR_DELAY_SEC` | `on`, `5-30` | Демо-отельер и задержка его ответов |
| `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB` | `okno` | База данных в Compose |
| `APP_STAGE`, `LOG_LEVEL`, `LOG_JSON` | `dev`, `INFO`, `false` | Режим и логи (stdout) |

Ресурсы: 4 ГБ свободной памяти и ~5 ГБ диска под образы. Все образы собираются под `linux/amd64`.
