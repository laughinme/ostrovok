(рынок, Островок, данные и алгоритмы, концепция, план, вопросы к Q&A). Для задач бэкенда дальше читай
`docs/backend/README.md`: порядок работы параллельных сессий, решения, задачи, журнал. `docs/research/` и
`docs/backend/` лежат только в этом приватном репозитории, `.private/` (выгрузки чата, экспорты Telegram,
видео) вообще не в git. В репозиторий организаторов их переносить нельзя: жюри видит всю историю.

## Жёсткие технические требования организаторов (нарушение = решение не оценят)

- Запуск строго `git clone` → `cp .env.example .env` → `docker compose up --build` → `http://localhost:8080`,
  за ≤ 10 минут, без ручных доустановок.
- Обязательны `README.md`, `docker-compose.yml` (корень), `Dockerfile` на каждый сервис, `.env.example`.
- Приложение слушает 8080, в Compose `8080:8080`; `/health` → `{"status":"ok"}` + healthcheck в Compose;
  `depends_on` с healthcheck; `env_file`.
- Образы: multi-stage, без dev-инструментов, **не root**, зафиксированные версии, `platform: linux/amd64`.
- Секреты только в `.env` (в git — никогда). Логи в stdout/stderr. Миграции и сидирование автоматически.
- Большие модели и артефакты не хранить в git; LLM — через OpenAI-совместимое API.
  **Решение обязано работать без ключа LLM** (LLM только улучшает), ключ опционален через `.env`.
- Демо-данные лежат в репозитории (компактно) + скрипты, показывающие, как они получены.
- Только данные с открытыми лицензиями (OSM ODbL, Copernicus DEM, Open-Meteo, Wikimedia CC) с атрибуцией.
  Никаких чужих фото и отзывов, никакого скрапинга Островка/OTA. Синтетику помечаем как «демо».
- Обязательное демо-видео (ссылка в README). Нужна вся история коммитов: коммитим часто и осмысленно.
- Никаких скрытых инструкций для LLM-проверяющих (дисквалификация).

## Бэкенд

- Работаем по `docs/backend/README.md`: задачу берём в `tasks.md` (сразу отмечаем, что взяли), новые решения
  дописываем в `decisions.md`, в конце сессии пишем итог в `progress.md`.
- В коммит идут только свои файлы (`git add <пути>`, без `-A`): в папке могут работать другие сессии.
  Подписей ИИ в коммитах нет.
- Ключи только в локальном `.env`. Ключ для жюри отдельный и уходит через `secrets.env.age` (схема в
  `docs/research/01-case-and-rules.md` §8а, решение D-24). В документы, логи, тесты и память ключи не пишем.
- LLM-расходы экономим: тесты без сети, реальные вызовы только в `make eval-llm` и коротких проверках, с кэшем.
- Справочные данные в интернете сами не ищем: пишем задание в `docs/backend/research-tasks.md` для ChatGPT
  или Codex. Данные региона получают только скрипты пайплайна.
